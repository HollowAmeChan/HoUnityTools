## 2. 曲线 / 修饰符 / 树的行为（总则）

### 2.1 三条不能忘的规则（§3.2 / §3.3）

* **曲线是夹的、不外推**（`HoFaceCurve.Transfer`，`HoFaceMiddleware.cs:15`）：范围之外按端点算。想留住负半边或超过 1 的轴**必须用宽曲线** —— 现在 `Form` / `Open` / `Funnel` / `Pucker` / `X` / `Press` / `Brow*Y` 都是 `±2` 就是为此；改成默认 `0…1` 会把负半边**压平**。`Lid/*/BlinkWide` 是 `−1…1`。
* **区域门是常量行、不过曲线**（`HoFaceAnimationSession.cs:316`：走 `defaultValue`，不调 `Transform`），写 1 就是 1；**但修饰符照走**。要改就改 `defaultValue`。
* **死区只有曲线能做精确**（树里「两行同姿势」的平台会被远处的孩子按距离权重掺进来，不是平的）。

### 2.2 背景：轴超出槽位范围会怎样（**2026-09-27 实测**，§2.3.1）

| 轴的位置 | Unity 的行为 |
| --- | --- |
| 在网格内部 | ⚠️ **不是分段线性**：非对称点实测与手算差最多 ~6%（(0.2,0.3) 得 129.93 而手算 121.3） |
| 超出网格（两侧都测了） | **投影到圈边、再用那条边的两个端点混合** ⇒ 落点永远在「最外围孩子围成的圈」上（x=−3 与 x=−1 同值） |
| 缺一角 | 圈被切掉一块 ⇒ 圈外那一侧落在**缺口那条新边**的两个邻居中间（(1,1) → 151.5） |
| 退化摆法（三点表 / 点压在别人的线上） | **圈内外跳变**（(0,0.5)=166.67 而 (−0.5,0.5)=100）⇒ 别让一个孩子落在别的孩子构成的边/线上 |

⇒ **一句话**：输出永远在「最外围孩子围成的圈」里面，**永不外推**。所以「轴超了」最坏是停在圈上，不会画出畸形造型。
代价：① 分辨率白扔；② 树与 Hub 会不一致（Hub 读到的是超出的原值）；③ 「0.4 = 半格」不成立（格内由引擎距离权重决定，不能手算）；④ 圈的形状决定停在哪儿。

⚠️ **Inspector 里两个别碰的地方**（§2.3.1）：**`Compute Positions` 按钮绝对不要点**（姿势片段没有位移 ⇒ 所有孩子被算到 (0,0)，整棵树塌）；**`Normalize Blend Values` 复选框别勾**（Direct 上它真的会归一化 ⇒ 区域权重和 4 被除成 0.25）。

**「量程/放大」的两条路 + 实际选择**（§2.3.1）：

| 路 | 怎么做 | 代价 |
| --- | --- | --- |
| **A · 挪槽位** ✅ **2026-09-27 已落地** | `Mouth/Open` 的 Y 刻度从 `0 / .5 / 1` 改成 **`0 / .4 / .75`**，外加逐格移位（右上角 `X2Y2` 单独摆 **0.6**）；检查器会核对刻度并钉死坐标 | Hub / 面板 / Warudo 读到的**仍是原始值**（0.75 = 满）；插值形状本就不可手算；顶边变斜 |
| **B · 中间层曲线** 🟡 只用来做死区 | 曲线横轴是表达式的值、纵轴是写出去的值 | 轴上写出去的就是曲线给出的数 ⇒ Hub / Warudo 一起受益；但三份 profile 副本要一起更新。**量程没有走 B** |

⚠️ **2026-09-28 深夜新增的 8 根权重轴（`Lid/*/Weight/*`）故意不挂**：它们是归一化后的凸权重，四个相加必须**精确** = 1（各自独立平滑会让 Σ 在过渡期 < 1 ⇒ Direct 的 `(1−Σw)·default` 漏进来）（§1 第 6 项）。

**为什么门与切片不挂**（§3.2）：区域门是常量行（挂 `smooth` 只会在开场把 1 从 0 爬上来）；4 条切片权重还没接进树，接的时候**四条必须用同一个时间常数**（线性滤波下「和恒为 1」才守得住）。

**修饰符写法**（§3.2）：

```json
"modifiers": [ { "kind": "smooth", "seconds": 0.009, "steps": [] } ]
```

* `kind`：`smooth`（时间常数，`seconds`）/ `steps`（维持：`steps[]` = `{trigger, target, hold, threshold}`，按 trigger 升序）/ `delay`（⚠️ 两端不一致：Unity 侧真的按每行 FIFO 延迟了、mod 侧会跳过它 ⇒ 要两端一致就先别用 `delay`）。
* ⚠️ **出口行带平滑 ≠ 轴被平滑**：两批行各自独立求值（轴行不引用出口行），VB 那 23 条 `smooth` 只作用在出口上 ⇒ 轴上的取值是**又挂了一遍**（照同族数值抄，不是共享同一个滤波器）。
* ⚠️ **短促事件别用大平滑**：眨眼、眼球扫视如果嫌抖，先想「是不是该用 `steps` 维持」，加大 `smooth` 会把它们糊成慢动作。
* ⭐ **`steps`（维持）就是 Schmitt 触发器**：过 `trigger` 跳到 `target`，掉回 `trigger − |threshold|` 以下才退，触发后至少保持 `hold` 秒。**输出恒等于 `target`（不是读数）**；⇒ **喂给它的必须是连续读数，不能是已经比过的 0/1**（§5.6 / §5.7.27 ①）。一行的完整形状：`表达式 = 连续读数` → `维持(trigger, target 1, threshold, hold)` → `平滑(过渡时长)`，**顺序不能反**（修饰符按列出顺序生效）。

**调参时必须知道的四条**（§3.2）：① 曲线夹、不外推；② 区域门常量行不过曲线（改 `defaultValue`）；③ 改 `Funnel` / `Press` 的公式或修饰符时**4 条切片行的内联副本要跟着改**（输出行之间不能互相引用）；④ `Gate/Expr/*` 中间层不写 = 谁都能写它。

**数值卫生：极小值归零**（§3.2，2026-09-27）：会话在**修饰符之后、写出去之前**做一次 `value != 0 && |value| < 1e-6 ⇒ 0`。起因是面板 `0.0000` / 影子台 `−4.949414e-40` 的**非规格化数**；实测排除了我们这几行（静息时 33 根轴全部精确 0、5 个门精确 1）⇒ 只可能来自输入侧。

### 2.5 三层分工：改手感时改哪一层（§3.3）

| 你想改的 | 改哪 | 为什么不能改另一层 |
| --- | --- | --- |
| **轴的口径**（同一个脸状态应该给出什么数：量程 / 死区 / 放大负侧） | **中间层 · 响应曲线**（必要时表达式） | 树的槽位坐标只是**常量标签**，它不产生值；挪刻度后 Hub / 面板 / Warudo 读到的仍是原值 |
| **某个轴值该长什么样**（−1 那格是噘嘴还是垂嘴角） | **树 · 槽位里的姿势内容**（片段） | 中间层不知道模型上有哪些键、怎么摆 |
| **采样点位置**（这个姿势该出现在 0.4 还是 0.5） | **树 · 槽位坐标** | 是艺术决定；**不要**用它代替量程归一 |
| **抖 / 跳 / 跟手慢** | **中间层 · 修饰符**（`smooth` / `steps`），偶尔曲线斜率 | **树没有时间概念**（静态插值机） |

### 2.6 怎么测（协议，§2.4 / §3.5）

① 丢一次追踪（清掉平滑与残留状态）→ ② 设备上点校准、对准镜头 → ③ 连做**三次** 5 秒静止（面板「记 5 秒」，每次 314…317 帧）→ ④ 定阈值取三次的 **`max`**（最坏情况），看常态取 `avg`。
⚠️ **单帧读数一律不作数**（同一动作逐帧差很多）。面板「配置输出行」栏每行右边的覆盖按钮可以把某根轴**钉成 −1 / 0 / 1** 手动试。
⚠️ **面板上看到「只有 0 / 1」是正常的**（挂了「维持」的行显示的是「状态亮没亮」，不是原始读数）—— §5.7.17 的教训：**别拿这根轴的显示值去调门**。

## 3. 嘴（12 根轴 + 1 根风格行）

### 3.1 `Ho/Drive/Mouth/Form`

* **谁消费**：`MouthCore` 的 X 轴（以及 `MouthCoreRoll` 变体版）；`Ho/Drive/Lid/<侧>/Form` 的**负侧**读它的负半轴（2026-09-28 深夜，§5.7.34 / §5.7.36）。
* **表达式（原文，2026-09-28 版）**：`((mouthSmileRight + mouthSmileLeft + ((mouthDimpleLeft + mouthDimpleRight) / 2)) - 2 * max((mouthFrownLeft + mouthFrownRight) / 2, clamp(((mouthStretchLeft + mouthStretchRight) / 2 - (0.42 * jawOpen + 0.05)) * 1.5, 0, 1))) / 2`
  （2026-09-28 **负半轴改成 sad**：闭嘴走 `frown`、张嘴走 `stretch` 残差；「噘」不再在这根轴里）

```text
  Ho/Style/MouthWidth/Read    = ((dimpleR + dimpleL) * 2 - mouthPucker) * out("…/CatMouthGate")     ← 宽度读数
  Ho/Style/MouthWidth         = if(out("Ho/Style/InvertedV"), -0.09, out("…/Read"))                 ← 噘嘴时归中（−0.09 = 表的中刻度）
  Ho/Drive/Mouth/Pucker       = out("Ho/Style/MouthWidth")                                          ← 转发（名字不变 ⇒ 资产不动）
  Ho/Style/MouthGate          = 1                                                                   ← 基准：常量 1（门恒开）
```

* **机制 = 输出表缓存**（`HoFaceOutputTable`）：所有行读写**同一张** `名字 → 这一帧已写的值` 的表，行按顺序写进去、**后写覆盖先写**，**整份配置走完之后才统一发布** ⇒ ① 「别的行读到的 / 面板读到的 / 发出去的值」永远是同一个；② 同名多行天然成立 ⇒ 「读自己写自己」的链就是规则二；③ `out("…")` 读的是**上面最近写过这个名字**的那一行 ⇒ 发布值是**最后写的那一行**（§5.6）。
* ⚠️ **修饰符仍然安全**：表的键是**名字**，修饰符状态是**每一行自己的**；行读到的是那一行**过完曲线与修饰符**的值，与「它会不会被后面的同名行覆盖」无关；也读不到自己 ⇒ **没有反馈环**（读只能朝上 ⇒ 依赖图按构造是 DAG）。⚠️ **链的第一条同名行不能读自己** ⇒ 所以规则二要有那条**基准行**打底；两条链行的 `defaultValue` 都是 **1**（万一无效则门**开着**）。
* ⭐ **风格形态之间不再互相覆盖（2026-09-29 用户定）**：用户原话「**先不要做风格表现的互相覆盖，只做他们自己要强制覆盖的东西，避免测试中立刻开始耦合**」。
  ⇒ ① `Ho/Style/CatMouth` 去掉 `× (1 − 鼓嘴)`；② `Ho/Style/InvertedV` 去掉 `× (1 − 鼓嘴) × (1 − 猫嘴)`；③ 两条 `MouthGate` 链行删除（只留常量 1 ⇒ 门恒开）；④ 输出行 180 → **178**。
  **各形态自己的门照旧保留**：鼓嘴的颊门 + 死区（0.05/0.05、0.40/0.05）、猫嘴的嘴角门 + 下颌增益（`1 + 3·jawOpen²`）、倒V 的死区（0.41/0.02）+ 鼻门（0.54/0.05）；`HoAuto*` / `HoExternal*` 开关照旧。
