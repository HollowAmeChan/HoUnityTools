# 眨眼约束（自动眨眼 + 果冻眼）设计

`HoUnityTools/Constraints/Ho Blink Constraint`。一个组件、两个模块：

- **自动眨眼**：程序化生成眨眼曲线，写到网格的眼睑形态键上，同时把值作为内部驱动暴露出去。
- **果冻眼**：读形态键（眨眼键、眼睛左右/上下运动键等），过一遍弹簧-阻尼，映射到用户自建的键（高光位置、眼仁形状、眼睑附加形变……）。

两者共用同一套**规则 / 目标映射**结构，也共用同一套键名引用方式。

## 设计约束（本版按反馈定稿）

- **不做形态键目录/按表查询**。内置一份**写死的键名表**（只覆盖眼睑与凝视），面板里以下拉形式给出，条目显示成 `键名 (规范)`（如 `Blink (VRM1)`、`まばたき (MMD)`）。用户自建的键直接手填文本。
- **键名存储是 `string` + 下拉**：手填与预设走同一套存储，加键不需要改代码。
- **不做左右眼之间的随机差异**，也不做"左右独立眨眼"。眨眼只有一个计时器，输出一个值；"单眼版本 / 双眼版本"指的是**模型上有哪些键**（一个双眼键，还是左右两个键），不是两套独立时序。需要 wink 这类单眼动作时用显式 API。
- **果冻弹簧是每条规则自己的**（一条驱动一套响应）。
- **组件不持有大量整体参数**；每个小映射（目标）自带自己的 ramp 与增益/范围。
- **用户不细调 ramp**：目标上只给"ramp 预设 + 强度"两个旋钮，原始曲线/时间常数收进 `自定义` 档。动态超调（甩一下再回来）**只由规则级弹簧负责**，ramp 只做"这一路的幅度形状与快慢"，避免两个弹簧互相打架（见「目标 ramp」一节）。
- **眯眼/睁大键不占基础流程**：它们照常在内置表里可手选，但只由**预设的高级模式**自动接线。
- 只写形态键（`SetBlendShapeWeight`），不碰 Transform、不碰材质，因此和 Animation Rigging / MC2 没有写者冲突。

## 适用范围与非目标

适用范围：

- 任何带 Blendshape 的 `SkinnedMeshRenderer`（人形、兽形、道具眼睛都行）。
- 面捕/动画已经驱动眼睑键时，可以只把它当"果冻眼"用（自动眨眼关掉）。
- 模型只有双眼键、或只有左右键，都要能用。

非目标：

- 不做形态键之间的拓扑运算（不合并形状、不改 mesh）。
- 不做眼睛的 Transform / 材质属性动画（那属于摆锤约束或 shader 参数绑定）。
- 不自己实现面捕/动捕输入；只**读**别人写好的形态键值。
- 不做左右眼独立随机眨眼（见上）。
- 不做口型/表情的通用映射（结构上能复用，但预设只覆盖眼睛）。

## 术语

| 术语 | 含义 |
| --- | --- |
| **网格列表** | 组件写入/读取的目标 `Renderer` 集合（运行时解析出 `SkinnedMeshRenderer`） |
| **形态键 / 键** | Blendshape，Unity 侧取值 `0..100` |
| **内置键名表** | 写死的 `(键名, 规范标签)` 列表：眼睑（闭合/眯/睁大）与凝视（上下左右/内外） |
| **驱动（Driver）** | 一条规则读取的源：形态键值，或内置的 `AutoBlink` 值，或调试用滑杆 |
| **规则（Rule）** | 以"读哪个键"为主体的一条映射；内含一段果冻弹簧和复数个目标 |
| **目标（Target）** | 一条规则里的一个输出映射项：写哪个网格的哪个键、怎么换算、自己的 ramp |
| **ramp 预设** | 目标级的成形方式（幅度形状 + 一阶时间包络），只给"预设 + 强度"两个旋钮，原始曲线收在 `自定义` 档 |
| **基准值** | 本帧我们介入之前，该键在网格上的值（通常是动画/面捕写的） |

## 数据流

```
网格键值 ──读──┐
自动眨眼 ──────┼─→ 驱动值(单极 0..1 / 双极 −1..1) ─→[可选]输入平滑 ─→[可选]弹簧-阻尼
手动滑杆 ──────┘                                                        │
                                                                        ▼
                        目标映射（每条目标自己的 ramp/增益/偏移/范围/权重）─→ 输出值
                                                                        │
                                        先取基准快照 → 覆盖 or 叠加 ────→ SetBlendShapeWeight
```

## 数据模型

### 目标网格

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `renderers` | `List<Renderer>` | 接受任意 `Renderer`（与 MC2 的 `sourceRenderers` 一致）；运行时解析出 `SkinnedMeshRenderer`，非蒙皮或没有 mesh 的项跳过并在面板里标黄 |
| `collectChildren` | 按钮 | 一键收集子级里所有 `SkinnedMeshRenderer` |

- 每个网格缓存 `Dictionary<键名, 索引>`，在 `sharedMesh` 变化（换装/mesh 重建）时重建。
- 不判断"这个网格属于哪套规范"：键名怎么解析只看**网格上实际有哪些键**；下拉里出现的 `(规范)` 只是给人和预设看的标签。

### 键引用（内置表 + 手填）

- 序列化存储就是一个 **`string keyName`**：任何键都能填，预设与内置表只是填值的来源。
- 面板里这一格是"下拉 + 文本框"：
  - 下拉内容 = 内置键名表（显示 `键名 (规范)`）+ 当前网格上实际存在的键名（命中内置表的在名字后带规范标签，未命中的标 `自定义`）+ `自定义…` 项。
  - 选 `自定义…` 后就是纯文本输入。
- 命中但网格上不存在时，该行标黄，面板顶部汇总"3 个键在目标网格上不存在"。
- 匹配规则（仅为容错，不做语义推断）：精确名 → 忽略大小写 → 剥 Blender 重复后缀（`Blink.001`）。同名键出现在多个网格上时默认全部写入。

### 驱动（规则的主体）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `driverKind` | `ShapeKey / AutoBlink / Manual` | `AutoBlink` = 自动眨眼模块本帧的输出值 |
| `positiveKey` | 键引用 | 正向键（`ShapeKey` 时必填） |
| `negativeKey` | 键引用（可空） | 负向键，用于把一对键合成带符号的轴（如 `LookRight − LookLeft`） |
| `driverRange` | `Unipolar / Bipolar` | 单极：值域 `0..1`；双极：`(正 − 负) / 100`，值域 `−1..1` |
| `invert` | bool | 反相 |
| `readWrittenThisFrame` | bool | 默认关：读**基准快照**（切断自反馈）。打开后按规则顺序读本帧已写入的值，可以自建链式联动；读写同一个键时面板给警告 |
| `missingPolicy` | `Skip / Warn / Error` | 驱动键找不到时的行为 |

### 规则

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `label` | string | 面板标题（默认自动生成，如 `Blink_L`） |
| `enabled` | bool | 整条规则开关 |
| `jelly` | 段 | 这条规则的果冻弹簧参数（见下） |
| `targets` | `List<HoBlinkTarget>` | 复数个目标映射项 |

### 目标映射项

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `meshScope` | `全部 / 指定` | 全部 | 写入范围 |
| `meshIndex` | int | 0 | `指定`时的网格下标 |
| `keyName` | 键引用 | — | 输出键 |
| `blendMode` | `覆盖 / 叠加` | 叠加 | `叠加` = 基准值 + 映射结果；`覆盖` = 直接写映射结果 |
| `gain` | float | 1 | 可为负（反相） |
| `offset` | float | 0 | 加性偏置 |
| `outputMin/Max` | float | 0 / 100 | 输出范围（允许负值或 > 100） |
| `clampToRange` | bool | true | 关掉可以做超范围驱动 |
| `weight` | 0..1 | 1 | 与基准/累加结果混合 |
| **`ramp`** | 段 | — | **这个小映射自己的成形方式**（见「目标 ramp」一节）： |
| `rampPreset` | 枚举 | `直通` | `直通 / 柔跟 / 放大 / 缓入 / 慢放 / 阶梯 / 自定义` |
| `rampIntensity` | 0..2 | 1 | 唯一的细调旋钮：按预设定义的语义缩放（放大倍率、时间常数、超调幅度） |
| `rampCurve` | `AnimationCurve` | 线性 | 仅 `自定义` 档出现：驱动值 → 输出值的形状（**允许 > 1**） |
| `rampAttack` | float（秒） | 0 | 仅 `自定义` 档出现：上升时间常数（一阶） |
| `rampRelease` | float（秒） | 0 | 仅 `自定义` 档出现：回落时间常数（一阶） |

- `ramp` 是**每条目标独立**的：同一份弹簧输出可以既驱动"高光位移"（直通、跟得紧）又驱动"眼仁形变"（缓入 + 慢放）。
- `attack/release` 的状态也是每条目标各自维护，互不影响。
- 跨规则写同一个键时：`叠加` 类的贡献相加，`覆盖` 类按规则顺序后写者胜。

## 每帧流程与不变量

1. **构建**（`OnEnable` / 网格变化时）：解析网格 → 解析每条驱动/目标的键索引 → 编译成扁平数组（无每帧字典查找、无 GC）。缺失键汇总成清单。
2. **快照**：一次性读入所有涉及键的当前值（基准值），之后本帧不再读网格。
3. **驱动**：算自动眨眼 → 得到 `AutoBlink` 值；读各驱动键 → 合成驱动值 → 输入平滑 → 弹簧。
4. **映射**：对每个目标算输出值（增益/偏移 → ramp 预设的形状 → 强度 → attack/release 包络 → 范围/权重）。
5. **合并**：按目标键聚合（叠加相加 / 覆盖后者胜），与基准值合成最终值，最后按「合并方式」处理超过 100 的情况（见下节）。
6. **写回**：只在 `|新值 − 上次写入值| > 0.01` 时调用 `SetBlendShapeWeight`；写过的键记入"本帧已写"集合。

### 时序契约

- 默认 **`LateUpdate`**（和摆锤/漂浮一致）：消费者是渲染，写在动画之后才能覆盖/叠加动画；这里没有同帧下游读者。
- 提供 `更新时机` 选项（`LateUpdate / Update / FixedUpdate / 手动`）：只有当**别的约束在 `Update` 里读这些键值**时才需要提前，按 `docs/FOLLOW_CONSTRAINT.md` 的时序契约办。

### 基准快照（重要不变量）

本帧所有驱动读的都是**快照值**，因此：

- 自动眨眼写眼睑键、同时某条规则又读眨眼键时，不会自己喂自己（反馈被切断）。
- 想表达"眨眼时压扁高光"，用 `AutoBlink` 驱动，而不是去读我们自己写的眨眼键。
- 要真正的链式联动，把规则的 `readWrittenThisFrame` 打开，此时规则顺序变成有意义的求值顺序。

## 形态键为什么老是写死 100（合并方式与饱和诊断）

形态键的合法区间是 `0..100`，而一个键上可能同时有好几个写者。求和在 100 处夹断，就会看到"不管怎么调都是 100"。实际有三种完全不同的来源，对策也不同：

| 来源 | 特征 | 对策 |
| --- | --- | --- |
| **单路自己就拉满** | 基准 0 + 我们 100 → 100，没有被削 | 这是"设计如此"。想留余量：调小该路「增益 / 强度」，或把「输出上限」从 100 压到 85~90，或让 ramp 预设别用「放大」 |
| **多路叠加被夹断** | 两路各要 80/70，加起来 150，夹成 100 —— 两路的比例、果冻超调全没了 | 把「合并方式」换成**软饱和**（永远不到 100，超调看得见）或**按比例分配**（两路一起缩、比例不变） |
| **外部基准已占满** | 基准本身 60~100（面捕/动画/VRChat 表情写着），我们再叠就顶死 | 「合并方式 = 按比例分配」会按剩余空间分配；或者该键改用 `Override` 混合模式；也要确认读的是基准快照（默认如此，自反馈已被切断） |

**合并方式**（`mergeMode`，眨眼与注视各自一个下拉）只作用于**我们自己这一路**：`sum = 0` 时输出恒等于基准，绝不会改写动画/面捕写在键上的值。

| 取值 | 规则 | 满值 |
| --- | --- | --- |
| `Saturate`（默认，老行为） | 求和后夹到 0..100 | 请求 ≥ 100 就是 100 |
| `SoftClip` | 80 以上软压缩：`80 + 20·(1 − e^−(x−80)/20)` | 请求 100 → 约 93；渐近但永远不到 100 |
| `Normalize` | 超过剩余空间时各路按同一比例缩小 | 请求 150 → 100，但 80/70 变成 53/47（比例保持） |

**饱和诊断**：写入器每帧记下每个绑定的「基准 / 我们请求的原始和 / 实际写出值 / 是否被削」，面板的调试区把它们列出来：

```
以下形态键已经写满（或我们这一路被合并策略削过）：
· EyeBlink_L　基准 0 + 我们 100 → 100
· EyeHighlight　基准 40 + 我们 120 → 92.6（被削）
```

看到「被削」就是多路叠加或基准占位在打架，按上表换合并方式；看到「基准 0 + 我们 100 → 100」就是单路到顶，属于正常，要余量就压输出上限。

## 关掉规则 / 关掉约束时的清场（硬写覆盖）

没人再写的时候，我们写过的键不会自己回到原样 —— 必须有人**硬写**回去：

| 时机 | 行为 |
| --- | --- |
| 规则被关掉（`Enabled = false`），目标还挂在写入器里 | 求和里这一路变 0，键自然回到基准 —— **前提是基准没被我们自己污染**（见下） |
| 规则被删 / 目标被移除 / 网格列表变化（重建后那个键不再有人写） | 重建收尾时把它**硬写回基准**（不看写入阈值），否则它会永远停在我们最后一次写的值上 |
| 组件被禁用、取消「允许写入」、`ResetState()` / 面板「重置」 | `RestoreWritten()` 把这一轮写过的键**全部硬写回基准** |

关键不变量：**重建不许把我们自己的输出当成外部基准**。写入器跨重建记住"上一轮写过哪些键、写之前的基准是多少"：

- 重建后仍在写的键 → 继承 `ExternalBase / LastWritten`，于是关掉规则那一帧就能算出"基准 + 0"并写回去；
- 重建后不再写的键 → 用记下来的基准硬写清场。

没有这条，任何一次重建（改规则、换网格、改键名）都会把当时的输出冻成新基准 —— 表现正是"规则一关，键还停在那个值上，怎么都不回 0"。

⚠️ 我们**只还自己拿过的键**：没写过的键（`EverWritten` 为假）一个都不碰，不会顺手改掉动画/面捕写下的值。

## 自动眨眼模型

### 状态机（单计时器）

```
等待(wait) ──间隔到──→ 闭合(closing, closeDuration) ──→ 保持(hold, holdDuration)
   ↑                                                        │
   └────────── 间隔(openDuration 结束 → 重新抽间隔) ←── 张开(opening)
```

- 一个计时器、一个输出值；左右眼由**输出键**决定（一个双眼键，或左右两个键拿同一个值）。
- 间隔抽自 `intervalMin..intervalMax`；`指数分布`模式用 `−mean·ln(1−u)`，比均匀分布更像真人。
- 双击：张开后以 `doubleBlinkChance` 概率在 `doubleBlinkGap` 后立刻再眨一次。
- 眨眼曲线：`AnimationCurve`（横轴 = 归一化相位，纵轴 = 闭合量），默认"快闭慢开"；默认 `闭合 80ms / 保持 40ms / 张开 140ms`。
- 长帧安全：一帧内跨多个阶段时按顺序推进，不丢阶段、不卡住；`deltaTime` 异常大时直接跳到"等待"并重抽间隔。
- 外部接管：若"接管键"（默认眼睑键）基准值持续高于阈值（默认 `5`）超过 `0.5s`，自动眨眼暂停 `2s` —— 面捕/动画在眨眼时不要和程序化眨眼打架。
- 对外 API：`TriggerBlink()`（双眼，走完整曲线）/ `TriggerBlink(left01, right01)`（显式左右，供 wink 用）/ `SetAutoBlinkEnabled(bool)`。

### 参数

| 字段 | 中文 | 范围 | 默认 |
| --- | --- | --- | --- |
| `blinkEnabled` | 启用自动眨眼 | bool | 开 |
| `intervalMin/Max` | 间隔下限/上限 | 0.5–20 s | 2.0 / 6.0 |
| `intervalDistribution` | 间隔分布 | 均匀/指数 | 指数 |
| `closeDuration` | 闭合时长 | 0.02–0.5 s | 0.08 |
| `holdDuration` | 保持时长 | 0–0.5 s | 0.04 |
| `openDuration` | 张开时长 | 0.02–0.8 s | 0.14 |
| `blinkCurve` | 眨眼曲线 | AnimationCurve | 快闭慢开 |
| `strength` | 强度 | 0–1 | 1 |
| `doubleBlinkChance` | 双击概率 | 0–1 | 0.15 |
| `doubleBlinkGap` | 双击间隔 | 0.05–1 s | 0.16 |
| `randomSeed` | 随机种子 | int | 0（0 = 用实例 id） |
| `pauseWhenDriven` | 被驱动时暂停 | bool | 开 |
| `pauseThreshold` / `pauseDuration` | 接管阈值/暂停时长 | 0–100 / 0–10 s | 5 / 2 |
| `blinkTargets` | 眨眼输出 | `List<HoBlinkTarget>` | 预设填充 |

## 果冻眼模型

读一个驱动值 → 一阶平滑 → 二阶弹簧-阻尼（半隐式欧拉，`maxStep` 子步保证帧率无关）：

```
a = ω²(target − x) − 2ζω·v        ω = 2πf
v += a·dt ; x += v·dt
```

- `f` 决定"跟得上多快"（高光跟眼睛 3–6 Hz 比较像果冻），`ζ` 决定回弹（`0.2–0.35` 有明显果冻感，`1` 为临界阻尼不超调）。
- 驱动本身是跳变的（面捕键值），弹簧负责把它变成"甩一下再回来"；再往下每个目标自己的 `ramp` 决定这一路怎么成形。
- 长帧/暂停保护与摆锤求解器同一套约定：`maxStep` + `Sanitize` + 复位时清速度。

| 字段 | 中文 | 范围 | 默认 |
| --- | --- | --- | --- |
| `jellyEnabled` | 启用果冻 | bool | 开 |
| `frequency` | 频率 | 0.1–20 Hz | 4.0 |
| `dampingRatio` | 阻尼比 | 0.05–2 | 0.25 |
| `inputSmoothing` | 输入平滑 | 0–0.5 s | 0.03 |
| `maxStep` | 子步上限 | 0.002–0.05 s | 0.016 |
| `resetOnEnable` | 启用时复位 | bool | 开 |

## 目标 ramp（成形方式）

ramp 管的是"这一路输出怎么成形"，不负责产生果冻感。

**分工（重要）**：

- **动态超调**（甩过头再回来）**只由规则级弹簧负责**（频率 + 阻尼比，一处调，物理上只有一个来源）。
- **ramp** 只做两件事：**幅度形状**（含 `> 1` 的放大，也就是"超出"的静态版本）与**时间包络**（attack / release 一阶跟随，无超调）。
- 两个旋钮：`ramp 预设` + `强度`。原始曲线与时间常数只在 `自定义` 档出现，避免用户到处细调。

| 预设 | 形状（驱动 → 输出） | attack / release（强度 = 1） | 强度改什么 |
| --- | --- | --- | --- |
| `直通`（默认） | `y = x` | 0 / 0 | 输出倍率（1.0 → ×1，2.0 → ×2） |
| `柔跟` | 缓入缓出 | 60 ms / 120 ms | 时间常数 ÷ 强度（越大越快） |
| `放大` | `y = 1.25x`（可超出目标范围） | 0 / 0 | 放大倍率 = `1 + 0.25 × 强度` |
| `缓入` | 起步慢、后段快 | 120 ms / 200 ms | 时间常数 ÷ 强度 |
| `慢放` | 线性 | 40 ms / 400 ms | release ÷ 强度（越大松得越慢） |
| `阶梯` | 立即跳到 1 并保持 | 0 / 0 | 无（离散形变用） |
| `自定义` | 用户曲线（**允许 > 1**） | 用户填 | 不参与（曲线/时间都归用户） |

- 默认建议：**多数目标用 `直通`**，果冻感交给弹簧；只有"这一路要更夸张"或"要更黏"时才换 `放大` / `慢放` / `缓入`。
- 需要"幅度超出但不要抖动"时用 `放大` 或自定义曲线（静态超出）；需要"甩一下"时回来调规则的阻尼比 —— 两条路各自独立，不会互相抵消。
- `ramp` 曲线允许超过 1，且 `clampToRange` 关掉时输出可以超过目标范围（配合"超出"用法）。

## 预设

预设做两件事：**把键名填进驱动/目标/眨眼输出**，以及**给每条目标选好 `ramp 预设` 与起点参数**。用户自建的高光/眼仁键始终手填。

预设面板分**基础**与**高级**两档（顶栏一个 `高级模式` 勾选）：

- 基础：眨眼输出两套、凝视两套、果冻组合三个 —— 覆盖"闭眼 + 高光跟眼"这类日常需求。
- 高级：眯眼/睁大相关的那几套，以及批量工具（把所有目标的 ramp 预设统一设成某个值、批量改强度）。

### 眨眼输出

| 档 | 预设 | 填什么 | 适用 |
| --- | --- | --- | --- |
| 基础 | `双眼键版` | 一个双眼闭眼键（`Blink` / `vrc.blink` / `まばたき` / `EyeClosed`） | 只有一个双眼键的模型 |
| 基础 | `左右键版` | 左眼键 + 右眼键，两者拿同一个值 | 只有左右键的模型（ARKit 型、Meta、PICO、SRanipal、OpenXR） |
| 高级 | `左右键版（含眯眼）` | 左右闭眼键 + 左右眯眼键（眯眼走同一驱动的次级目标，`ramp` 用 `缓入`） | 想要"闭眼顺带眯一下"的模型 |
| 高级 | `左右键版（含眯眼 + 睁大）` | 再加左右睁大键（反向目标：睁大 = 1 − 闭眼） | 需要"睁大"跟随的模型 |

- 应用时若所选键在网格上不存在，面板给出提示并推荐同语义里存在的那个（例如选了 `Blink` 但网格上只有 `Blink_L/Blink_R` → 提示改用 `左右键版`）。

- 眯眼/睁大键在内置表里随时可以手选，高级预设只是把接线自动化。

### 交互细则

- **规则列表**用 `ReorderableList`：拖拽排序，每条规则一个折叠头，标题 = `驱动摘要 → N 个目标`，右侧放启用勾选与"缺失键"图标。
- **键名格**：下拉（分组：眼睑 / 凝视 / 当前网格实际存在的键 / `自定义…`），条目显示 `键名 (规范)`；选中后可以直接在旁边的文本框里改。命中但网格上不存在时标黄。
- **目标行**：常显"键 + 增益 + `ramp 预设` + 强度"，`偏移`、`输出范围`、`钳制`、`权重`、`混合模式` 与（`自定义` 档的）原始曲线收在行内一个"细节"折叠里，列表才不至于太胖。
- **缺失键**：面板顶部汇总 `HelpBox`："3 个键在目标网格上不存在"，附"重新解析"按钮。
- **预设**：顶栏下拉；只填充与所选部分相关的字段，不覆盖用户已手填的键名；提供"复制/粘贴配置"（JSON）方便跨模型搬运。
- **多选编辑**：同 `HoPendulumConstraint`，多实例选中时批量应用预设。

- 面板顶部一行实时读数：当前眨眼相位、输出值、网格/绑定计数。

## 调试工作流

| 现象 | 先看什么 | 常见原因 |
| --- | --- | --- |
| 完全不眨眼 | 调试区驱动值；缺失键汇总 | 眨眼输出键没解析到（键名拼错/网格没放进来） |
| 眨眼了但动画也在眨 | 目标的混合模式与基准值读数 | 用了 `覆盖` 覆盖动画；改 `叠加` 或打开"接管判定" |
| 果冻感太硬 / 不回弹 | **规则的阻尼比、频率** | ζ 太高（≥0.7）；或输入平滑太大把阶跃抹平了 |
| 幅度不够 / 过了 | 目标的 `ramp 预设` 与强度 | 该换 `放大`；或强度不等于 1 |
| 高光跟不满 / 过冲 | 目标增益、值域（单极/双极） | 单极/双极选错；`In/Out` 与 `Left/Right` 混族 |
| 抽搐/抖动 | 驱动键原始值读数 | 面捕键值本身抖动 → 加输入平滑；或 spring 频率过高 |
| 眨眼"拖泥带水" | 目标的 `ramp 预设`（换成 `直通`）与强度 | 用了 `慢放`/`缓入`；或强度的语义被误解（时间常数 ÷ 强度） |
| 停帧后爆掉 | `maxStep` | 长帧没有子步（对齐摆锤的长帧处理） |
| 只有一半网格动 | 网格列表与 `meshScope` | 该网格缺这个键（缺失键汇总里能看到） |
| 形态键总是 100，怎么调都一样 | 调试区的饱和清单 | 见「形态键为什么老是写死 100」：单路到顶（压增益/输出上限）／多路叠加被夹断（换软饱和或按比例分配）／外部基准占满（按比例分配或改 `覆盖`） |
| 果冻的超调看不见 | 目标是不是已经写满 | 输出被夹在 100：把「输出上限」压到 85，或把「合并方式」换成软饱和 |

## 性能与资源约束

- 构建期完成全部键解析；每帧只做数组遍历，无字典/无 LINQ/无分配。
- 阈值写 + 上次值缓存；同一个键每帧最多写一次。
- 规则/目标编译成扁平数组（规模是几十个量级，托管数组即可）。
- `sharedMesh` 变化才重建索引；`OnDisable` 释放缓存。
- 调试字符串只在面板可见时生成。

## 里程碑与验收

1. **键名表 + 解析器 + 键下拉**：给一个真实模型，下拉里能同时看到内置条目和该模型实际存在的键，并标出哪些内置键在模型上不存在。验收：ARKit 型（只有左右）与 VRM1 型（有 `Blink`）都能选对。
2. **自动眨眼 + 眨眼输出**：程序化眨眼可见、可调、可在编辑器预览；双眼键版/左右键版两套预设可用。验收：闭合时长/间隔统计符合参数；被面捕驱动时自动让位；左右两眼的值始终一致。
3. **规则列表 + 果冻弹簧 + 目标 ramp**（核心）：高光/眼仁联动可用。验收：驱动阶跃时输出有可调的超调与回落（超调来自规则弹簧）；同一条规则下两个目标可以用不同 ramp 预设（一个 `直通`、一个 `缓入`）；只动"预设 + 强度"就能把效果调到可用；静止时收敛不漂移。
4. **预设整套**：基础档（眨眼输出两套、凝视两套、果冻三个）+ 高级档（含眯眼/睁大、批量工具）。
5. **调试视图 + 文档实测数据**：把长帧、面捕抖动、混族等场景的实测结论补进本文档。
6. **文档回填**：`ramp 预设表`里"强度改什么"的数值要按实际手感复核一遍（现在写的是设计意图，不是实测值）。
