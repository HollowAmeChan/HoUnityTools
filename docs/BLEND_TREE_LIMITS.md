# 混合树的能力边界

日期：2026-09-22。起因：在面捕的中间层分工上反复踩到"这件事到底该放树里还是放外面"，
而且我（助手）一度把边界说错了。这份文档把**能算什么、不能算什么、以及怎么判断**一次写清，
以后不必靠印象争。

> **一句话**：混合树不是"参数进、任意函数出"的表达式求值器。
> 它是**姿势插值机** —— 输出永远是"作者摆过的那些姿势的加权组合"，
> 权重只能由参数经门控层级**线性地**合成；而且它**写不了 Animator 参数**，只能写对象上的属性。

## 1. 它到底算什么（精确模型）

Direct 树对**每一个属性**的结果是：

```
输出 = Σᵢ (Πⱼ 门控ᵢⱼ) · 值ᵢ   +   (1 − Σw) · 默认值        然后按属性自身的范围钳制
```

- `值ᵢ` 是**作者摆的常量**（片段里写的形态键值 / 位移 / 材质参数）。树自己不产生数。
- `门控ᵢⱼ` 是参数值。**嵌套一层 Direct，门控就多乘一次**（实测：0.6 × 0.8 → 48）。
- **`Σw > 1` 时不做归一化**（实测：同一属性 0.6 + 0.8 → **140**，不是 70、也不是 80）。
  也就是"两个子节点各给一份"就是**相加**，Unity 不会替你平均 ——
  **裸的直通树为什么会过眨眼，根因就在这里**。
- 余项 `(1 − Σw)` 与**默认值**混合；WD 开时那个"默认值"是**Animator 启动时捕获的值**（实测）。
- 最后被属性范围钳制 —— 形态键就是 0~100。**这是唯一的"上限"机制**，果冻超调靠它露出来。

**推论：它是一台"以参数为变量的多项式机器 + 钳制"。**
这条推论决定了下面所有"能 / 不能"。

## 2. 能表达什么（附配方）

| 想要的 | 怎么做 | 状态 |
| --- | --- | --- |
| 加权和 `Σ wᵢ·Cᵢ` | 多个子节点写同一个属性 | 实测 |
| **乘积 `a · b`** | 嵌套 Direct：外层门控 `a`，里层门控 `b` | **实测：0.6 × 0.8 → 48** |
| **加权平均 `(a+b)/2`** | 两个子节点写同一属性，**值摆成一半**（50），门控给出 a、b | **实测**（相加不归一化 ⇒ 系数就是那个 50） |
| 反向 `1 − a` | 同一属性上两个子节点分别写 1 与 0，权重取 `a` | 由上面的加法推得 |
| 幂 `a²` | 同一个门控套两层 | 由"嵌套相乘"推得 |
| 上下限 / 饱和 | 属性自身的范围（0~100） | 实测（0.6/0.8 → 60/80；超出即钳） |
| 区域/模式开关 | 子树挂在父树上，权重 = 门控参数 | 实测（我们生成的区域门控） |
| 两版映射交叉淡入 | 一棵 1D 树，两个子节点分别是"OFF 版"和"ON 版"的子树 | 参考实现的 `EyeSync` |
| **把会重叠的语义并进同一棵树** | 2D 树 + 作者摆好的组合姿势（见 §6） | 实测（Jerry 的眼睑五姿势） |
| 分段（近似） | 多阈值子节点，段内是线性插值 | 实测（1D 树语义） |

> 参考实现那个 `EyeSyncMix = 0.5` 现在看懂了：它把"两只眼的值"当**加法**用，
> 而 0.5 不是为了"平均"，是为了**把加法除回一半**（两边都写一半 ⇒ 得到一只眼的量）。
> 它就是在没有归一化的前提下手工补上归一化系数。

## 3. 不能表达什么

| 做不到 | 为什么 |
| --- | --- |
| `min(a,b)` / `max(a,b)` | 不是参数的多项式组合 |
| 除法 `a / b` | 同上 |
| 任意非线性（`sin`、`smoothstep`、软饱和曲线） | 同上；只能靠多个阈值**线性近似** |
| **任何需要记忆的**：弹簧、平滑、回弹、带回差的阈值、随机 | 树**没有时间轴、没有状态** —— 它是参数的纯函数 |
| **产生一个新的参数值** | 见 §4。树只能写对象属性，写不了 Animator 参数 |
| 精确的分段（"小于 X 就是 0"） | 只能线性近似，除非用 `Step` 那种离散档 |

一条实用的判断法：**把你要的映射写成一个表达式，看它是不是"参数的多项式组合 + 钳制"。**
是 → 树能做（可能要多层门控）；出现 `min`/`max`/除法/时间 → 树做不到。

## 4. 三条"逃生口"，以及各自的代价

树做不到的事，只有这四个去处：

| 逃生口 | 能做什么 | 代价 |
| --- | --- | --- |
| **在控制器外面算**（我们的做法） | 任意 | 需要宿主能跑 C#：Unity / Warudo 可以，**VRChat 不行** |
| **VRChat 曲线驱动参数** | 在控制器**内**产生新参数，闭环 | VRChat **客户端特性**，Unity 里没有；参考实现整套 `OSCm/Proxy/*` 靠它。我们已推迟 |
| **曲线 + 哑组件 + C# 读回** | 同上，但在 Unity 里也能跑 | **一帧延迟** + 一段 C# + 一个哑组件当锚（曲线绑不到参数，只能绑组件属性） |
| **StateMachineBehaviour**（挂状态上，`OnStateUpdate` 里 `SetFloat`） | 在控制器内跑任意 C# | 依赖我们的代码进构建；一个状态一个行为；**我们现在的 `Compile` 明确拒绝 Behaviour** |

**注意第二条和第三条的本质**：Unity 里**曲线绑不到 Animator 参数**，
能绑的只有对象属性。所以"让树输出一个参数给下游读"这条路，
在纯 Unity 里必须经过**一次 C# 转运**，并且**晚一帧**。

## 5. 设计前的三个自问

1. **我要的是"姿势"还是"值"？**
   姿势 → 直接进树（含重叠语义的合并）。值要给别人用 → 看第 4 节。
2. **写成表达式，它是不是"参数的多项式组合 + 钳制"？**
   是 → 树能做；否（`min`/`max`/除法/时间）→ 外面算。
3. **必须留在控制器内闭环（不能加 C#）吗？**
   那就只剩 VRChat 曲线驱动参数那条路 —— 我们已经推迟它（见 `FACE_TRACKING_PIPELINE_SPLIT.md` 第 14 节）。

## 6. 一个正面例子：会重叠的语义要并进同一棵树

ARKit 的 `eyeBlink` 与 `eyeSquint` 在模型上闭的是同一块，裸输入里两者同时非 0 →
同一个形变被写两遍 → 过眨眼。参考实现的解法**不是**在参数上做抑制，而是：

**把这三个键写进同一批姿势，用一棵 2D 树插值**（实测五个片段的内容）：

| 姿势 | blink | squint | wide |
| --- | --- | --- | --- |
| 睁大 | 0 | 0 | **100** |
| 中性 | 0 | 0 | 0 |
| 闭 | **100** | 0 | 0 |
| **眯** | **90** | **100** | 0 |
| 睁大+眯 | 0 | 0 | **100** |

关键在**「眯」那格自带 blink 90**：两个轴走到哪就是哪个姿势，**权重和恒为 1，不可能相加**。
这也解释了"为什么眼睑是 2D 而嘴是 1D"——不是好看，是必须。

## 7. 证据与不确定性

原先带 ★ 的两条**已经量掉了**（`.research` 探针台，同一套 `HO_*` 用例）：

| 条目 | 状态 | 结果 |
| --- | --- | --- |
| 不同属性、多子节点的 Direct 权重 = 各写各的 `w×100` | **实测** | 0.6 / 0.8 → 60 / 80，不被归一化削弱 |
| **同一属性**被多个子节点写 | **实测** | 0.6 + 0.8 → **140** ⇒ **相加，且不归一化** |
| **嵌套 Direct 的门控相乘** | **实测** | 0.6 × 0.8 → **48** |
| `Σw > 1` 时是否归一化 | **实测** | **不归一化**（就是上面那个 140） |
| WD 开时余项混的是"启动时捕获的值" | **实测** | 0.6×100 + 0.4×33 = 73.2 |
| 权重 0 的子树**不碰**那个属性 | **实测** | 预置 33 保持 33 |

仍然**只是推断**的（由上面三条推出的合成规则，没有单独量）：

- `1 − a`：靠"同一属性写 1 和 0、权重取 a" —— 若 Unity 对**同属性多子节点**的处理在
  WD 关闭 / 归一化设置变化时改行为，这条要重验。**目前 WD 开 + Direct 是唯一被验证过的组合。**
- `a²`：同一个门控套两层 —— 由"嵌套相乘"直接推出，但没单独跑过。
- 2D（FreeformCartesian）树里的权重和是否也恒为 1：**没有直接量过**；
  §6 那个"姿势不可能相加"的结论依赖它。（眼睑现在的实现就吃这条，值得补一个用例。）

**结论**：本文档 §2 表里除了那两条明说"推得"的，都是实测。
`Σw > 1` 不归一化这一条尤其要紧 —— 它同时解释了
"裸直通树为什么会过眨眼"和"参考实现为什么需要 `EyeSyncMix = 0.5`"。
