# 摆锤约束设计与验证

## 适用范围

摆锤约束（`HoUnityTools/Constraints/Ho Pendulum Constraint`）把锚点的运动解算成一组摆锤参数，再通过绑定写到材质属性、Shader 全局、UnityEvent 或另一个 Transform。

它解决的问题和旧 `Wobble.cs` 一样：给液面 shader 提供摆动参数。区别在于它是通用组件，输出不再写死成两个材质 float。

它**不写自身 Transform**，定位是参数生成器。要驱动物体就加一条 `Transform` 绑定指向子物体；绑定指向驱动源自身时会被跳过并给出警告，避免自反馈。

当前只实现**弹簧摆**模型（倾斜自由度 + 竖直方向的径向弹簧）。绳索链（多段绳子摆动、逐关节输出）是另一套模型，单独规划。

## 与旧 Wobble 脚本的差异

| 项 | 旧 Wobble | 摆锤约束 |
| --- | --- | --- |
| 驱动量 | 线速度 + 角速度（`(lastPos - pos)/dt`，取负） | 锚点**加速度**，由最近若干帧位置的二次最小二乘拟合给出 |
| 帧率 | 振幅增量没乘 `dt`，60fps 输出约为 30fps 的两倍 | 自动分子步（默认 1/240），阶跃响应在 1/15~1/240 完全一致 |
| 加速度估计 | 无（速度驱动） | 二次最小二乘拟合：对匀速与恒加速精确，抗位置抖动能力比逐帧二阶差分高一个数量级 |
| 频率 | `WobbleSpeed` 直接乘绝对时间，改参数会跳相位 | 液面响应频率独立给定（默认 3Hz），相位累加；摆长只影响可视化与离心半径 |
| 总响应延迟 | 约 0.18s 的隐含滞后 | 估计窗口 (N-1)/2 帧 + 加速度平滑 + 平衡角平滑（默认 6 帧 + 60ms + 20ms） |
| 饱和 | `atan` 一味增长，靠夹取 | 合成幅值夹取 + 可调软饱和；对角晃动不会到 √2 倍上限 |
| 竖直方向 | 只有两轴倾斜，上下颠簸没有输出 | 径向弹簧给出有效重力与伸长量，上下颠簸有明确响应 |
| 重力/朝向 | 无 | 有效重力方向决定平衡面，物体翻转时液面跟着翻转 |
| 双轴相位 | X/Z 共用 `sin(time)`，只沿一条对角线摆 | 双轴各自独立积分，可打圈 |
| 角速度 | 欧拉角直接相减，±180° 处跳变 | 用四元数增量求角速度，另加物理离心项 |
| 材质写入 | MPB + `mat.SetFloat`（污染共享材质资产） | 默认只写 MPB；需要兼容旧行为时勾选「同时写材质资产」 |
| 输出 | 写死 `_WobbleX` / `_WobbleZ` | 18 个通道 × 4 种绑定目标 |
## 模型

平衡面（全部在锚点本地坐标系）：

```text
vertical    = 球面插值(up, localUp, 朝向跟随)        // 完全反向时绕任意垂直轴旋转，不会塌成零向量
centrifugal = ω × (ω × r)                          // r = -up * 摆长
a_f         = 一阶低通(a, 加速度平滑)                // **只滤惯性项**，朝向项不受影响
drive       = a_f * 灵敏度 + 离心影响 * centrifugal
n_raw       = drive + vertical * g                 // 有效重力的反方向，就是液面平衡法线
g_eff       = |n_raw| / g                          // 有效重力倍率
θ_eq        = (atan2(n.x, |n.y|), atan2(n.z, |n.y|)) 只做数值保护（89.5°），不按最大倾斜角压缩
θ_eq_filter = 一阶低通(θ_eq, 平衡角平滑)             // 直流增益为 1
```

倾斜自由度按阻尼谐振子追赶平衡角：

```text
θ'' = -ω²(θ - θ_eq_filter) - 2ζω θ'      // ω = 2π * 液面响应频率
θ   = 限幅(θ_eq_filter + 软饱和(θ - θ_eq_filter, 最大倾斜角))   // 只夹相对平衡面的摆动幅度
```

`最大倾斜角` 限制的是**摆动幅度**而不是平衡角本身：平衡角必须能一路走到 90°/180°，液面才能在任何朝向下都屈服于重力（瓶子放平、倒过来都对）。

竖直方向是一维弹簧，静止伸长为 ΔL 时刚度由重力标定：

```text
x'' = -ω_r²(x - x_eq) - 2ζ_r ω_r x'
x_eq = ΔL * (g_eff / g - 1)              // 静止 0，过载为正，失重为负
ω_r  = √(g / ΔL)                         // ΔL = 0.02m 时约 3.5Hz
```

半隐式欧拉积分，按 `最大子步` 自动分子步。

### 长帧 / 暂停的鲁棒性（切出窗口变 NaN 的那一类问题）

`[ExecuteAlways]` 的组件在编辑器里也会跑，而"切出去再回来、编辑器卡顿、域重载、GC 长停"都会产生一个**异常大的帧间隔**。这里有三个独立的坑，缺一个就会出现"液面参数变 NaN，只能重进 Play 才恢复"：

| # | 坑 | 现在的处理 |
| --- | --- | --- |
| 1 | 子步数被钳在 64，于是 `step = delta / 64` 可以**远超** `maxStep`。半隐式欧拉在 `ω·h > 2` 时数值发散，径向弹簧（`ω_r = √(g/ΔL)`，ΔL=0.015 时 25.6 rad/s）按 `(ω_r·h)²` 几何增长，64 步就溢出成 `Infinity`，再靠 `Infinity − Infinity` 变成 NaN | 子步长同时受 `maxStep` 与**刚度稳定边界**约束（`h ≤ 0.5 / ω`），并且长帧只模拟 `64 × h` 那一段——宁可这一帧动画慢一点，也不超步长 |
| 2 | 径向弹簧**没有任何物理夹取**（角度那一路有 `ClampDeviation`），所以先炸的总是 `_LiquidOffset` | 径向偏移按 `max(12 × 静止伸长, 0.1m)` 夹取，并把继续朝外的速度清零 |
| 3 | 状态里一旦留下 NaN，之后每帧都会重算出 NaN，**自己不会恢复** | 每帧积分后检查状态是否有限，非有限就就地复位到平衡位姿（输出里带 `recovered` 标记，约束侧只提醒一次）。派生输出再兜一道，绝不让 NaN 通过绑定写进材质属性 |

另外运动估计器也加了暂停识别：帧间隔超过 0.25s 就丢掉历史样本重新起步。否则二次拟合会跨过那个大洞，编出一个几十 m/s² 的假加速度，液面会突然抽一下。

实测（harness 的「长帧鲁棒性」一节）：

| 单帧 delta | 修正前径向偏移峰值 | 修正后 |
| --- | --- | --- |
| 100 ~ 2000ms | 0.0035m（正常） | 0.0035m |
| 5000ms | **2.8 × 10³³ m**（驱动值 1.2 × 10²⁶） | **0.0035m** |

再加两条断言钉住边界：ΔL=0.5mm + `最大子步`=0.5s（面板上限）+ 5s 长帧不发散；以及把 `NaN`/`Infinity` 直接写进状态后，**当帧**就能自愈并置位 `recovered`。

几个直接推论（都已作为断言验证）：

- 恒加速度稳态满足 `tan θ = a / g`（柔和度为 0 时严格成立；默认 0.65 且倾角远低于上限时误差 < 0.5°）。
- 匀速平移的加速度为 0，不会产生稳态倾斜。
- 朝向跟随为 1 时液面保持世界水平：物体侧倾 30°，输出倾角就是 30°；完全倒置时平衡角为 0 而不是 180°。
- 朝向跟随为 0 时液面跟随物体自身轴，但仍然响应加速度。
- 摆长 L 对应的无阻尼周期为 `2π√(L/g)`（勾选「摆长决定频率」时使用），与固有频率 `1/f` 一致。
- 纯竖直运动不产生倾斜（物理正确），但会产生有效重力变化与径向伸缩。
- 1Hz 往复运动下的总相位滞后约 **20°**，旧默认参数下约 **164°**（旧默认把 1Hz 的谐振点放在手持运动频段里，液面几乎反相）。

按帧采样会带来约半帧的群延迟，这是任何离线采样的仿真都有的：低帧率下瞬时值会有相位差，但包络与帧率无关（实测 1/480~1/15 包络偏差 0.38%）。

## 面板结构

分区默认全部折叠，展开状态在同一次编辑器会话内保持（脚本重编译不会丢）。折叠时只看四行摘要：

| 分区 | 折叠时的摘要 | 内容 |
| --- | --- | --- |
| 基本 | 驱动源 · 频率 · 最大角 | 驱动源、液面响应频率（含「摆长决定频率」）、阻尼比、最大倾斜角、加速度灵敏度 |
| 输出绑定 | N 条绑定 | 绑定列表（每条默认折叠，只有新增的那条自动展开）、是否同时写材质资产 |
| 高级 | 更新时机 · 拉伸 · 估计窗口 | 更新时机、摆长与朝向、饱和柔和度、竖直拉伸、采样、手动输入（仅手动模式显示）、初始变换 |
| 调试 | Gizmo 开 | 显示开关、颜色、绘制尺寸、运行时读数 |

顶部工具栏是「清空」与「水瓶液面」两个预设。日常只需要「基本」和「输出绑定」两栏，其余按需展开。

**面板文案规矩**：字段的工具提示只留"名字看不出来"的那一句话（单位、区间、关键区别），含义、调参区间、实测量级与推导一律放在本文档。面板里只额外显示**运行时才知道**的信息（由摆长换算的频率、包围盒测得的参考尺寸、运行时读数）。所以想搞清楚某个参数为什么是这个值，看文档而不是悬停在面板上。

## 参数

| 参数 | 含义 |
| --- | --- |
| 驱动源 | `自身运动` / `父级运动` / `指定锚点` / `手动输入` |
| 摆长 | 摆锤末端到锚点的静止距离；同时是离心项半径。默认**不**决定晃动频率 |
| 摆长决定频率 | 勾选后改用物理单摆频率 `√(g/L)/2π`，摆长越长晃得越慢 |
| 液面响应频率 | Hz。液面晃动快慢由容器与液体决定；手持运动在 0.5~2Hz，放在 2~3Hz 既能跟上倾斜、又不会与手的动作共振 |
| 阻尼比 | 1 为临界阻尼；液面建议 0.5~0.8（液体的黏性本来就大，0.15~0.3 那种来回振铃像果冻） |
| 最大倾斜角 | **相对平衡面**的摆动幅度上限（不是液面绝对倾角上限，平衡角不受它限制） |
| 饱和柔和度 | 0 为硬夹取，1 为最软。软饱和在线性区几乎不改变响应，只把接近上限的拐角磨圆 |
| 加速度灵敏度 | 1 为物理值。它只缩放**惯性项**，不影响「倾斜容器时液面屈服重力」 |
| 朝向跟随 | 1 表示液面平行于世界水平面，0 表示垂直于物体自身轴 |
| 离心影响 | 旋转离心加速度对液面的影响强度 |
| 参考重力 | 换算平衡角与径向弹簧用的 g |
| 启用竖直拉伸 | 竖直方向是否启用径向弹簧 |
| 静止伸长 | 1g 静止时的伸长量（米），同时决定径向弹簧频率 `√(g/ΔL)/2π`。0 表示刚性 |
| 径向阻尼比 | 竖直伸缩的阻尼比 |
| 加速度平滑 | 毫秒。只对**加速度**做一阶低通（世界空间，采样与手动输入统一），不滤朝向。默认 60，液面预设 120。见下节 |
| 平衡角平滑 | 毫秒。对平衡角做一阶低通，直流增益为 1，不影响稳态倾角。它会同时延迟「倾斜容器」的响应，所以优先用加速度平滑压抖动 |
| 最大子步 | 单步积分上限，默认 1/240。实际子步长还会被**刚度稳定边界**（`0.5 / ω`）压住，参数给太大也不会发散；长帧只模拟 `64 × 子步长` 那一段 |
| 估计窗口 | 帧。对最近这么多帧的位置做二次最小二乘拟合求速度与加速度。越大越抗抖动，代价是约 (窗口-1)/2 帧的额外滞后 |
| 手动加速度 / 输入值 / 输入上下限 / 输入加速度 / 输入轴 | 手动输入模式的驱动量；输入值按区间归一化后乘到输入加速度上 |

## 惯性项为什么要单独滤波

液面的倾斜由两件事决定，而它们的噪声特性完全不同：

| 项 | 来源 | 噪声 | 该不该滤 |
| --- | --- | --- | --- |
| **朝向项**（重力） | 容器相对世界竖直的方向 | 干净，就是 Transform 的旋转 | ❌ 不能滤：滤了就会出现"转动瓶子液面发肉" |
| **惯性项**（加速度） | 位置的二次拟合 | 手部抖动、位置量化、动画台阶 | ✅ 必须滤 |

早期版本只有「平衡角平滑」，它作用在**已经合成的**平衡角上，所以要么抖动没压住、要么把朝向响应一起拖慢。现在惯性项有独立的低通（`加速度平滑`），朝向项只经过 20~30ms 的平衡角平滑。

实测（60fps，把「手拿瓶子左右移动」的轨迹喂进估计器 + 求解器，量液面总倾角的峰峰值与 >6Hz 的抖动 RMS）：

| 场景 | 旧预设（灵敏度 1.0 / 上限 10° / 3Hz / ζ0.3） | 液面预设（灵敏度 0.5 / 上限 6° / 2.2Hz / ζ0.7 / 加速度平滑 120ms） |
| --- | --- | --- |
| 慢速搬运 1.2Hz 8cm | 峰峰 49.8° · 抖动 2.49° | 峰峰 **16.7°** · 抖动 **0.87°** |
| 走路晃动 2.0Hz 3cm | 峰峰 48.5° · 抖动 3.84° | 峰峰 **10.3°** · 抖动 **0.88°** |
| 用力摇动 3.0Hz 4cm | 峰峰 98.7° · 抖动 12.42° | 峰峰 **22.9°** · 抖动 **2.69°** |

旧预设的问题不是"噪声没滤干净"，而是**增益太大**：灵敏度 1.0 让液面 1:1 跟随手的加速度，而手的加速度尖峰轻易就到十几 m/s²，`atan(15/9.81) = 57°`——液面在左右移动时是在 ±25° 地来回翻（同时还把液体甩出液面网格，看起来时有时无），那个"颤抖"就是它。代价是响应变慢：3 m/s² 阶跃下 90% 建立时间从 117ms 变成 383ms（液体本来也该有这个滞后）。

**要继续调的话**：

| 想要 | 调什么 |
| --- | --- |
| 液面跟手更紧、更"活" | 加速度平滑 120 → 60ms，灵敏度 0.5 → 0.7 |
| 更黏、更重 | 阻尼比 0.7 → 0.9，频率 2.2 → 1.6Hz |
| 大幅度晃动更容易出现 | 最大倾斜角 6 → 10° |
| 倾斜容器时液面更跟手 | 平衡角平滑 30 → 10ms（它与手抖无关，只影响朝向响应） |

> `估计窗口` 也别再往上加：窗口 12 会带来 33° 的 1Hz 相位滞后，而它压的是**位置量化**噪声；
> 手抖属于真实运动，估计器不该背这个锅，那是 `加速度平滑` 的职责。

## 加速度估计

加速度不是逐帧二阶差分算的，而是对最近 N 帧位置做**二次最小二乘拟合**，取二次项系数：

- 对**匀速**精确（二次项为 0）——这是"持续移动不该抽搐"的关键；
- 对**恒加速**精确（位置本身就是二次的）；
- 时间戳用累计 `deltaTime`，因此编辑器里帧间隔不均匀也成立（脚本用固定步长调 `Evaluate(dt)` 时也成立）。

逐帧二阶差分 `a = Δ²p / dt²` 会把位置抖动放大 `1/dt²` 倍。实测（60fps，匀速横向移动）：

| 工况 | 二阶差分 | 二次拟合（窗口 6） | 改善 |
| --- | --- | --- | --- |
| 平滑匀速 | 0.001 m/s² | ~0 | — |
| 量化 1mm，v=0.20m/s | 2.94 m/s² | 0.42 m/s² | 7× |
| 量化 1mm，v=0.05m/s | 2.08 m/s² | 0.66 m/s² | 3.1× |
| 每 3 帧才更新位置（20Hz 采样） | **44.1 m/s²** | 1.58 m/s² | **28×** |
| 帧间隔抖动 ±30% | 4.84 m/s² | 0.31 m/s² | 15.4× |

44 m/s² 折算成倾角噪声是 77°，也就是液面在极限处来回翻；拟合后是 9°，再经过平衡角平滑与 3Hz 振荡器基本看不出抖动。

窗口长度的取舍（60fps，20Hz 台阶 vs 1Hz 正弦跟踪）：

| 窗口 | 台阶噪声 RMS | 1Hz 幅值误差 | 1Hz 相位滞后 |
| --- | --- | --- | --- |
| 3 | 44.1 m/s² | -0.1% | 6° |
| 5 | 6.3 m/s² | -0.4% | 12° |
| **6（默认）** | **1.58 m/s²** | -0.6% | 15° |
| 9 | 0.29 m/s² | -1.5% | 24° |
| 12 | 0.09 m/s² | -2.7% | 33° |

## 输出通道

| 通道 | 内容 |
| --- | --- |
| 液面倾斜 X / Z | `tan θ`，可直接喂给液面 shader 的 `_LiquidTiltX` / `_LiquidTiltZ` |
| 斜率向量 | `(TiltX, 0, TiltZ)` |
| 倾角 X / Z / 合倾角 | 度。合倾角是幅值，受最大倾斜角限制 |
| 旋转欧拉角 | `(AngleZ, 0, -AngleX)`，把局部 up 转到液面法线，适合让物体随液面倾斜 |
| 摆向 | 摆锤末端相对锚点的世界方向（单位向量） |
| 末端偏移 / 末端位置 | 摆锤末端相对锚点的本地偏移 / 世界坐标，**已含径向伸长** |
| 振幅 | 相对平衡位置的振荡幅度 0~1 |
| 相位 | 累加相位 0~2π |
| 归一化读数 | 手动输入模式为输入值映射，其余模式为倾角 X 相对最大角的映射 |
| 有效重力 | `g_eff / g`：静止 1，自由落体趋近 0，过载大于 1 |
| 伸长量 | 径向弹簧偏移（米）：静止 0，过载为正，失重为负 |
| 伸长量 ±1 | 上者按静止伸长归一化并夹取到 ±1 的斜坡：静止 0、过载 +1、失重 −1 |
| 锚点速度 / 角速度 / 加速度 | 诊断用 |

## 输出绑定

一条绑定 = 通道 + 缩放 + 偏置 + 目标。标量通道只用 x 分量。

| 目标 | 写入方式 |
| --- | --- |
| 渲染器属性 | 通过 `MaterialPropertyBlock` 写到指定渲染器；渲染器列表为空时按「包含子物体」自动收集 |
| Shader 全局 | `Shader.SetGlobalFloat` |
| UnityEvent | 向量通道走 `UnityEvent<Vector3>`，标量通道走 `UnityEvent<float>` |
| Transform | 按权重驱动目标 Transform 的本地旋转（欧拉角）或本地位置 |

渲染器写入的三个细节：

- 默认**不写材质资产**。旧 Wobble 的 `mat.SetFloat` 会污染共享材质、破坏合批，Warudo 打包后还会影响所有使用同一材质的人。需要兼容旧行为时勾选「同时写材质资产」。
- 同一帧内同一个渲染器只 `GetPropertyBlock` 一次，多条绑定写在同一个属性块上再 `SetPropertyBlock`，因此 `_LiquidTiltX` 与 `_LiquidTiltZ` 不会互相覆盖，同时也不会抹掉其他组件写入的属性。
- **`MaterialPropertyBlock` 写在 Renderer 上，必须还原**。首次写入某个渲染器之前会留一份它的原始属性块快照，组件**禁用 / 销毁 / 绑定被改动**时自动还原——否则最后写入的值会永久盖住材质本身的值，组件移除了也还在（表现为"参数锁死"，且材质面板的滑条看起来完全失效）。面板上还有「清除已写入的材质属性」按钮可以手动清一次。

## 水瓶液面预设

编辑器工具栏的「水瓶液面」按钮会清空绑定并建立**五条**渲染器属性绑定，同时套用下面那组参数：

| 通道 | 属性 | 缩放 | 量纲 |
| --- | --- | --- | --- |
| 液面倾斜 X° | `_LiquidTiltX` | 1 | 度 |
| 液面倾斜 Z° | `_LiquidTiltZ` | 1 | 度 |
| 伸长量 ±1 | `_LiquidOffset` | 0.01 | 网格本地单位 |
| 液面高度 | `_LiquidFill` | 1 | 0~1，**已按倒置翻转** |
| 振幅 | `_LiquidWaveAmpMul` | 1 | 波纹振幅的**乘数**（0~4，静止给 0） |

量纲按 lilToon 液体 shader（`lil_liquid_level.hlsl`）的契约：

| 属性 | 量纲 | 本约束怎么给 |
| --- | --- | --- |
| `_LiquidTiltX` / `_LiquidTiltZ` | **度**（shader 内 `tan(radians(...))`） | `atan2(-n.x, n.y)`、`atan2(-n.z, n.y)`，n = 世界 up 在锚点本地的表示 |
| `_LiquidOffset` | **网格本地单位**（与 `_LiquidLevelY/H` 同量纲）；`_LiquidOffsetMode=1` 时是量程百分比 | 径向弹簧伸长量的 ±1 斜坡 × 0.01 |
| `_LiquidFill` | 0~1，在 `_LiquidLevelY`~`_LiquidLevelH` 之间插值 | 组件 `FillAmount`（倒水逻辑写）在翻过 90° 时自动输出 `1 - 输入` |

几个要点：

- **倾斜角不是斜率**。shader 侧自己做 `tan()`，所以驱动端给角度，而且**必须用 `atan2` 而不是 `atan`**：`atan(-n.x/n.y)` 在 `n.y` 过零（容器放平）时从 `-90°` 跳到 `+90°`，容器连续转到倒置的过程中液面会突然翻一下——实测就是"倒转时有跳变"。`atan2` 连续单调地走 `0 → ±90 → ±180`，而 `tan` 以 180° 为周期，所以坡度在每一度上都正确。
- **`_LiquidOffset` 的 0.01 不是拍脑袋**：它是网格本地单位，而斜坡是 ±1，所以缩到 ±1%（0.01）。把 shader 的 `_LiquidOffsetMode` 设成 1，这个缩放就直接是"液面量程的百分之几"。
- shader 侧把 `_LiquidOffset`（以及波纹）加在"内部符号"**外面**，所以这个参数的语义是"液面在世界空间里往上走多少"，容器倒过来也是同一个方向——驱动端不必再判断朝向。
- 强度由「加速度灵敏度」和这两条倾斜绑定的缩放决定；`_LiquidOffset` 的幅度由 高级 → 竖直拉伸 → 静止伸长 决定。

### 倒转（容器翻转）怎么处理

倒置要做两件事，**一件在 shader、一件在驱动端**，缺一不可。这一点文档早期版本写错过（当时以为只要翻转 `_LiquidFill`），实测症状是"完全倒转时液面是倒过来的"。

#### ① shader：把"内部"换到另一侧（`lil_liquid_level.hlsl` 的 `lilLiquidInteriorSign`）

液面平面本身对 `n` 与 `-n` 是对称的（`tan(180°) = 0`），所以倾斜角、液面高度在倒置后给出的**平面**都是对的。但"哪半边是液体"是**半空间**的属性，不是平面的属性：高度场的内部恒定是 `d > 0`，也就是恒定含物体 `-Y` 的那一侧。容器翻过 90° 之后世界向下在物体空间里变成了 `+Y`，液体必须挂到 `+Y` 那一侧——换 `_LiquidFill`、换 `_LiquidOffset`、把倾角写成 180° 都做不到（`tan(180°)` 还是同一个半空间）。

所以 shader 侧按几何量自动翻转：

```hlsl
float3 worldDownOS   = -lilLiquidWorldUpOS();                // 物体空间里的世界向下（矩阵第 1 行）
float3 planeGradient = float3(tx, -1.0, tz);                 // ∇d（物体空间）
float  sign          = dot(planeGradient, worldDownOS) < 0.0 ? -1.0 : 1.0;
return d * sign + lilLiquidWave(p) + lilLiquidOffsetValue();
```

⚠️ 参与点积的两个向量必须在**同一个坐标系**里。`∇d` 是物体空间的，所以「世界向下」要用 `lilLiquidWorldUpOS()`（物体→世界矩阵的**第 1 行**）取，而**不是** `lilLiquidUpOS()`（第 1 **列**，那是"物体的 up 在世界空间"，只能和世界法线点积）。用错的话点积退化成 `cos(2φ)/cosφ`，它的零点在 **φ = 45°** —— 容器刚转到 45° 液面就提前倒转了（实测症状）。这个错误在 0°/90°/180° 时行与列恰好重合，所以正立和完全倒置都看不出来，只在中间角度暴露。

正立时 `sign` 恒为 `+1`（`∇d · 世界向下 = 1/n.y > 0`），所以对正立材质**完全无影响**；只有 `n.y < 0` 时才翻转，而且翻转发生在液面本身接近竖直的那一瞬间（±90° 附近 `tan` 发散、液面退化成一条线），看不到跳变。

#### ② 驱动端：翻转 `_LiquidFill`（满 → 0，空 → 1）

内部换了边，液面就要从网格本地 Y 的**另一端**开始量。本约束为此提供了「是否倒置」通道（1 = 已翻过 90°），预设绑定直接给的是已经翻转好的值：

```csharp
constraint.FillAmount = pourFill;      // 倒水 / 消耗逻辑照常写 0~1
// 绑定「液面高度 → _LiquidFill」拿到的是 Inverted ? 1 - pourFill : pourFill
```

要自己判断的话用 `constraint.Inverted`：

```csharp
float fill = constraint.Inverted > 0.5f ? 1f - pourFill : pourFill;
```

> ⚠️ 另外两个坑：①**别直接喂 `eulerAngles`**，它是旋转角不是坡度，`eulerAngles.x = 180°` 会被 Range 钳到 90°、`tan(90°)` 发散；②倒置时保持 `_LiquidTiltScale = 1`，否则 `tan(180° × scale)` 不再是 0。

验证方式（`HoPendulumHarness liquid`）：把容器绕 Z 轴从 0° 逐度转到 180°，对液面模型做网格采样，检查四个不变式——倾角连续、平面始终世界水平、液体始终在世界向下的一侧、液体占比连续。两个"对照"把两类错误各自的症状钉住了：

| 版本 | 内部换边 | 症状 |
| --- | --- | --- |
| 正确 | `dot(∇d, 第 1 行)` | 181 个角度全部通过，90° 处翻转 |
| 不做内部换边 | 恒取 `d > 0` | **从 91° 起挂错边**（"倒转时液面是倒过来的"） |
| 坐标系混用 | `dot(∇d, 第 1 列)` | **45° 就提前翻转**（"45 度就开始倒转了"） |

### 波纹：驱动的是"乘数"，不是幅度本身

lilToon 侧把波纹做成了**两路相乘**，这是为了给美术留一个总闸门：

```hlsl
最终振幅 = _LiquidWaveAmp * _LiquidWaveAmpMul
//         美术的手动基准      脚本每帧写的乘数
```

| 属性 | 谁写 | 量纲 | 说明 |
| --- | --- | --- | --- |
| `_LiquidWaveAmp` | **美术**（面板） | 0~0.2 | 基准幅度。**给 0 就等于把整条波纹通道关掉**——乘法才有这个"闸门"语义，加法做不到 |
| `_LiquidWaveAmpMul` | **约束**（每帧） | 0~4，静止 0 | 乘数。0 时最终振幅恒为 0，与手动值无关（静止就是静止） |

约束绑定的是**乘数**那一路（通道「振幅」= 相对平衡面的摆动幅度 / 最大倾斜角，0~1）：

- 静止时通道为 0 → 乘数 0 → 液面自动变平，不需要额外判断；
- 缩放取 **1**：含义是"晃得最厉害时，波纹正好等于美术给的基准幅度"；
- 实测手持场景下该通道峰值 0.53~0.66、RMS 0.41~0.55（三个场景见验证一节），没有长期贴着 1，所以还有调节余量——想让晃动时波纹更显眼，把这条绑定的缩放调到 1.5~2（量程 0~4 够用），或者直接调大材质上的 `_LiquidWaveAmp`。

> ⚠️ 材质上的 `_LiquidWaveAmp` 默认是 **0**，所以只接脚本这条绑定是看不到波纹的——必须先在材质面板给它一个非 0 基准值。这是刻意的："这个容器要不要波纹"归美术，"这一刻波纹多强"归脚本。



| 帧率 | 旧 Wobble RMS | 旧 Wobble 峰值 | 摆锤 `tanθ` RMS | 比值 |
| --- | --- | --- | --- | --- |
| 60fps | 0.16073 | 0.44995 | 0.06631 | 2.42 |
| 30fps | 0.07804 | 0.22620 | 0.06630 | 1.18 |

旧脚本的比值随帧率变化（因为振幅增量没有乘 `dt`），摆锤约束的比值恒为 1。**新写的液面 shader 如果把 `_LiquidTiltX` / `_LiquidTiltZ` 直接当斜率用，把两条绑定的缩放改成 1**；2.4 只在 shader 侧沿用旧 shader 那套量纲时才有意义。

## 接入别的 shader

当前出厂对接的是 lilToon 液体家族（`Hidden/lilToonLiquid`，见上一节与 `lilToon/LILTOON_液体着色器设计.md`）：属性是**度**，`tan()` 在 shader 侧做。

要接别的液面 shader，按它需要的量纲选通道，**别改灵敏度去凑**：

| shader 要什么 | 用哪个通道 | 说明 |
| --- | --- | --- |
| 两个倾斜角（度） | `TiltXDegrees` / `TiltZDegrees` | 直接就是 lilToon 的契约，容器倒置时连续走到 ±180 |
| 两个斜率（tan，无上限） | `TiltX` / `TiltZ` | 本地轴斜率，已按 ±89° 夹取，不会给出发散值 |
| 世界空间斜率 | `WorldTiltX` / `WorldTiltZ` | 静止时对任何朝向恒为 0（液面完全屈服重力），+z 侧抬高为正 |
| 液面法线（向量） | `Tilt` + `VerticalAlignment`，或 `Swing` | `(TiltX, VerticalAlignment, TiltZ)` 就是本地空间的液面法线 |
| 液面升降（±1 斜坡） | `StretchNormalized` | 静止 0、过载 +1、失重 −1；shader 侧自己乘高度幅度 |
| 液面高度（0~1） | `FillAmount` | 已按倒置翻转，直接就是 `_LiquidFill` |

在世界空间构造液面平面时只有一条要注意：**高度项要除以物体缩放**（世界米 → 物体空间单位），而**倾斜项不要重复除**——倾斜项本来就乘在世界偏移上，再除一次会让摆动强度小两个数量级（旧 shader 的 `_WobbleX` / `_WobbleZ` 就是因为这个在 98 倍缩放的液面物体上基本失效）。

## 水瓶液面预设的其余参数

| 参数 | 值 | 理由 |
| --- | --- | --- |
| 液面响应频率 | **2.2Hz** | 手持运动在 0.5~2Hz，放在这里既能跟上倾斜、又不会与手的动作共振 |
| 阻尼比 | **0.7** | 接近临界阻尼：液体的黏性本来就大，ζ=0.3 的来回振铃看起来像果冻 |
| 加速度灵敏度 | **0.5** | 只缩放惯性项。1.0 是物理值，但手的加速度尖峰常到十几 m/s²，1:1 跟随会让液面 ±25° 地翻（见「惯性项为什么要单独滤波」的实测表） |
| 最大倾斜角 | **6°** | 相对平衡面的摆动幅度上限。6° 是一眼能看出晃动、又不会把液面甩出液体网格的量级 |
| 饱和柔和度 | 0.7 | 接近上限时圆滑压缩，不像撞墙 |
| 摆长 | 0.25m | 只影响可视化与离心半径 |
| 静止伸长 | 0.015m | 径向弹簧，约 4Hz |
| 估计窗口 | 8 帧 | 压位置量化噪声；再加会把 1Hz 相位滞后推到 30° 以上 |
| 加速度平滑 / 平衡角平滑 | 120ms / 30ms | 前者压手抖（只滤惯性项），后者兜住剩下的一阶噪声；后者再大会让"倾斜容器"的响应发肉 |

3 m/s² 阶跃下的建立时间：63% 用 217ms、90% 用 383ms、无过冲。也就是说液面稳态倾角是 `atan(0.5 × a / g)`（3 m/s² → 8.7°，7 m/s² → 19.6°），但要多花 0.2~0.4 秒才到位 —— 这正好是"液体"该有的手感。要更跟手就把加速度平滑降到 60ms。

判断当前设置是否合适，直接看调试视图里的**红色加速度箭头**：匀速移动时箭头应该几乎为零（只有启停瞬间有值）；如果箭头一直在乱抖，那是位置抖动，调大「估计窗口」；如果箭头稳定但液面还在大幅摆动，那是灵敏度的问题，调小灵敏度或调小最大倾斜角。

> 液面平面是绕**网格本地原点**旋转的（`level + tanθx·x + tanθz·z`），所以倾角越大，液体在网格里"流出去"的部分越多——倾斜 15° 时采样到的液体占比就从 30% 掉到 17%。这是平面模型的固有性质（参考实现也一样），**不是 bug，也决定不修**：按液体质心补 `_LiquidOffset`（`-tanθx·cx - tanθz·cz`）技术上可行，但补偿项会和晃动惯性挤同一个参数、把两件事重新耦合起来，收益远小于维护成本。液面模型只承诺"朝向正确"。

## 验证

数值验证（dotnet 直接引用 `UnityEngine.CoreModule.dll` 跑纯数学求解器，54 项）：

- 恒加速度稳态 `tanθ = a/g`，a 取 0.5~9.81 与负值，误差 < 0.05°（柔和度 0）。
- 默认参数（柔和度 0.65 + 35ms 平衡角滤波 + 径向弹簧）下中小角度误差 0.31°。
- 静止不产生倾斜；扰动后收敛回水平；小角度自由振荡周期 = `1/f`，误差 0%。
- 阶跃响应在 1/15~1/240 帧率下偏差 0°；正弦驱动包络在 1/480~1/15 下偏差 0.38%。
- `dt = 0` 不改变状态、不产生 NaN；NaN / Infinity 输入被过滤。
- 侧倾 30° 液面保持水平；完全倒置平衡角为 0；朝向跟随为 0 时回到物体自身轴。
- 软饱和：线性区不改变响应，接近上限时明显压缩，渐近线严格不越过最大角；柔和度为 0 时退化为硬夹取。
- 对角晃动按幅值夹取（10° 上限给出 10°，旧实现会到 14.14°）。
- 径向弹簧：静止有效重力 1、不伸长；向上加速 1g 时 `g_eff = 2`、伸长量翻倍；自由落体时 `g_eff → 0`、径向收缩；纯竖直运动不产生倾斜但有伸长；频率 = `√(g/ΔL)/2π`。
- 摆长 0.15~2.5m 的周期与 `2π√(L/g)` 一致，积分实测周期误差 < 0.5%。
- 1Hz 驱动的总相位滞后 20.09°（旧默认 163.89°）。
- 运动估计器：平滑匀速估计加速度 6e-5 m/s²（应为 0）、平滑恒加速精确、20Hz 采样台阶下噪声 1.58 vs 二阶差分 44.1 m/s²（28×）、帧间隔抖动 ±30% 时仍准确、样本不足时输出 0 而不是 NaN。

液面链路验证（`dotnet run --project Harness.csproj -- liquid`，另有一份表格输出）：
