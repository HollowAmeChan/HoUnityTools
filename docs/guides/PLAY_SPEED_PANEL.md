# 播放速度面板（速度条）

播放模式下直接改 `Time.timeScale` 的一条小面板：慢放看清某一帧、快进跳过没意思的一段，不用改代码重进 Play。

形态与图标都仿 dotsquid 的 **ChronoHelper**（一排速度点 + 非线性滑杆 + 数字格 + 复位 / 自动复位 / 警告闪烁）。
**图标字节是直接搬过来的**：那份工具是 **CC0 1.0**（公共领域奉献，见它包里的 `LICENSE.md` —— 可复制、可改写、可商用、不要求署名），
出处与皮肤选择写在 `Editor/PlaySpeed/HoPlaySpeedIcons.cs`。其余按本仓规矩重写：中文界面、配置进 EditorPrefs、速度控件保持单行。

| --- | --- |
| **速度条**（唯一入口） | 菜单 `HoUnityTools/播放速度` |
| **设置**（速度点 / 按钮 / 警告） | 速度条右边那颗齿轮按钮；或速度条的右键菜单。**故意没有菜单项**（2026-09-30 用户定：菜单里只留一个入口） |
| 配置存哪 | EditorPrefs 键 `com.hollow.hounitytools.playspeed`（**每台机器一份、不进仓库**） |
| 代码 | `Editor/PlaySpeed/`：`HoPlaySpeedWindow`（条）· `HoPlaySpeedSettingsWindow`（设置）· `HoPlaySpeedSettings`（数据与落盘）· `HoPlaySpeedPreset`（速度点与文字格式化）· `HoPlaySpeedIcons`（图标，CC0） |
| 自动化接口 / 场景配置 | `Runtime/PlaySpeed/`：`HoPlaySpeedControl` / `HoPlaySpeedOverride`；组件菜单 `HoUnityTools/播放速度/自动化倍率` |

## 30 秒上手

1. Play **之前**就把速度条打开：编辑模式下点速度点 / 拖滑杆设的值会记下来，按 Play 时生效。
2. 玩的时候照常点 / 拖 / 直接填数字（数字格能吃超过最大速度点的值，上限 100×）。
3. 自动化锁定时，info 显示请求脚本，关闭右侧「锁定」即可本次播放手动调试。
4. 退出播放还原实际倍率；开启「自动复位」时，面板期望值也回到播放前。自动化不会因关闭窗口而停止。

## 语义（别混）

| 东西 | 语义 |
| --- | --- |
| **速度点按钮** | **一次性**：点一下就是把期望速度设成它。面板**不记"当前选的是哪颗"**，按钮也没有按下状态 —— 现在多快看滑杆与数字格 |
| **自动复位**（齿轮左边那颗开关） | 开着：退出播放时期望速度还原成**进播放前**那个值（播放期间调的刻度不留下）；关着：保留，下次 Play 从它开始 |
| **复位**（按钮） | 当前速度与期望速度**一起**回到「本次播放开始时」那个值。**不在播放模式时按不动**（右键菜单里是灰的） |
| **警告** | 见下节：从不 / 总是 两档 |
| **锁定**（运行时布尔按钮） | 开启后调速控件禁用；关闭即本次播放手动接管，自动化重复请求不能抢回。再次开启才恢复请求倍率；不写进场景 / Prefab / EditorPrefs |

### MMD 影片与 BGM

`HoVmdSequencePlayer` 的动作、表情和镜头使用 `Time.deltaTime` 推进，BGM 跟随这条时间线：

- `0×` 暂停动作和音乐；恢复速度时音乐从当前时间继续。
- `0 < 速度 ≤ 3×` 时音乐的 `pitch` 跟随速度，因此音高也会变化。
- 超过 `3×` 时音乐暂停，动作与镜头继续快进；回到支持范围时音乐对齐当前时间恢复。
- 录制器设置 `ExternallyDriven` 时仍严格按 `ExternalTime` 采样，不受面板倍率影响。

2026-11-01 修复：旧实现把 `AudioSource.time` 当成动作的主时钟。
音乐游标不会跟着 `Time.timeScale` 自动变速，因此**有 BGM 且音乐正在播放时，面板虽然改成功了，动作仍会按音乐进度走**；
没有 BGM 或还在预热时却能正常变速，这就是一种“有时调速无效”的确定触发条件。

### 自动化显式声明倍率，用户可以临时接管

新建影片可在运行入口配置 `HoPlaySpeedOverride`，指定 `Speed`（常规 `1`）和 `LockPanel = true`。
组件进入 Play 自动申请倍率与锁定；面板 info 显示组件类型、对象名及倍率。
脚本也可直接请求：

```csharp
using Hollow.HoUnityTools.PlaySpeed;

void OnEnable()
{
    HoPlaySpeedControl.SetOverride(this, 1f, lockPanel: true);
}

void OnDisable()
{
    HoPlaySpeedControl.Release(this);
}
```

- API 只在播放模式申请，倍率限制 `[0, 100]`，非有限值拒绝。
- 后发的显式请求成为当前来源；旧来源 `Release` 不会清除新来源。
- 锁定后按钮、滑杆、数字格与复位不可编辑；**「锁定」开关始终可手动关闭**。
- 手动解锁只改变静态运行时状态，不改组件的序列化 `LockPanel`；同次播放即便脚本每帧重复申请或出现新来源，也不会自动抢回。
- 重新勾选「锁定」才恢复当前请求。关闭/隐藏窗口不终止请求；锁定由临时隐藏运行时驱动维护。
- 退出播放清除来源、锁定与手动接管。编辑器 `SessionState` 保留原始基准，开启自动复位时连播放期间的配置存盘也只存原始期望倍率。
- MMD 离线录制桥显式请求 `1×`，保证预热/物理不继承面板慢速；动作的 `ExternalTime` 离线采样仍独立。
- `HoVmdSequencePlayer` 普通播放、恢复或重新开始时同样显式请求并锁定 `1×`，不需要给旧场景补组件。暂停、自然结束、组件停用或交给外部采样时释放自己的请求；不会释放录制器等新来源的锁定。手动解锁后，恢复或重新开始仍尊重本次播放的手动接管。

### 普通外部改动仍跟随

外部（脚本、别的工具）改了 `Time.timeScale`，面板就把值收下来显示出去，并按警告设置闪一下。
没有通过上述接口声明的逐帧写入仍可能覆盖用户调试倍率，且无法可靠知道写入者；不要把它误报为某个脚本的锁定。
需要可追溯来源、可临时手动接管的自动化入口应使用 `HoPlaySpeedControl`。

## 外部改动警告

判据只有一条：**面板自己写完 `Time.timeScale` 是立刻一致的**，所以"对不上"只可能来自外部（脚本、别的工具、另一个面板）。
对不上时底色按警告色闪一下，闪够「闪多久」秒自己停。

| 警告模式 | 什么时候闪 |
| --- | --- |
| 从不 | 不闪（跟随照旧） |
| **总是**（默认） | 只要对不上就闪 |

注意：音乐主时钟、`unscaledTime` 等绕过缩放时间的播放逻辑，并没有改写 `Time.timeScale`，
因此这类“实际内容没有变速”不会触发外部改动警告。

（设置窗口的「测试闪烁」按钮可以直接看效果，不用真去找个脚本改速度。旧配置里存的是三档时代的数字，读取时会被夹进这两档。）

## 速度点

- 默认七颗：暂停 `0` · `⅛` · `¼` · `½` · `1` · `1.5` · `2`。`0×` 那颗画的是参考实现的暂停图标。
- **`0×` 与 `1×` 是保底点**：暂停与常速是面板的两个确定落点，少了它们只能靠手拖滑杆。删掉之后下次读取会自己补回来
  （值 0 与 1），所以「固定」标记实际只影响"界面上能不能删"。
- 按钮文字三档格式：`×0.125`（原样）· `×0.125`（短）· `×⅛`（紧凑，用 Unicode 分数符号：`⅒⅑⅛⅐⅙⅕¼⅓⅜⅖½⅗⅝⅔¾⅘⅚⅞`）。
  凑不到分数符号就退回小数 —— 不硬凑。数字一律按 `InvariantCulture` 排，免得跟着系统区域变成 `0,125`。
- 编辑数值时**不自动排序**（行会在手底下跳），要排就点「按值排序」。

## 布局

速度控件仍为一行（24px 高），右侧增加「锁定」开关。
有自动化来源、手动锁定或手动接管状态时，下方增加一条 info（总高 48px），完整说明可悬停查看。
最小宽度是算出来的（速度点那排 + 滑杆那块）：GUILayout 不给按钮换行，窗口比这更窄右边那几颗就被切掉 ——
与其画一排半拉按钮，不如把窗口撑到够宽。真嫌宽就在设置里切「按钮宽度 = 自适应」、「块顺序 = 反转」，或者把速度点删到够用。

## 硬规矩（改代码前先读）

1. **只在播放模式写 `Time.timeScale`**。编辑模式写它没有意义，还会把"进播放时那个值"这个复位基准弄脏。
2. **借了要还**：播放前基准由独立编辑器会话记录，退出播放还原实际倍率，自动复位决定是否还原期望倍率。
   普通面板关闭时还原；自动化请求不能因窗口关闭失效，交给来源释放或播放会话退出。
3. **来源显式、手动接管优先**。普通外部写入跟随；声明的自动化可以锁定，但不能绕过本次播放的手动解锁。
   锁定开关不写场景/Prefab，不把运行时状态混入 EditorPrefs。
4. **速度值夹在 `[0, 100]`**：0 是暂停（`Time.timeScale = 0` 是合法值），负数是没定义的，100 以上固定步长追不上。

数字格与滑杆只在用户实际编辑控件时回写速度。显示数字时的三位小数舍入不应改变真实倍率。
播放中点复位时，期望值必须与还原后的实际速度一致；进播放前预设的期望值仍留给退出播放的自动复位使用。

## 已知边界

- **窗口被折叠 / 切到别的页签时 `OnGUI` 不跑** ⇒ 外部改动要等下次重画才发现，粒度 **20Hz**（播放中每 50ms 重画一次；
  编辑模式完全不重画）。声明的自动化锁定由运行时驱动维护，不依赖 `OnGUI`。
- 直接逐帧写 `Time.timeScale` 的第三方脚本不受本接口的手动接管约定约束，需要改用显式请求接口。
- 播放前实际/期望倍率与手动接管标记使用编辑器 `SessionState` 保存，不因重编译丢失基准；
  场景组件会在重新启用时重新声明来源。
- **图标不做主题热切换**：`HoPlaySpeedIcons.Load()` 在窗口 `OnEnable` 时按当前皮肤挑好（深色皮肤取白线、浅色取黑线）。
  切了编辑器主题后重开一次窗口就对了 —— 那几张 `HideAndDontSave` 贴图由窗口自己销毁。
- **受影响的都是相对时间的东西**：`Time.time` / `Time.fixedDeltaTime` 推进的物理 / 动画 / `WaitForSeconds` / 粒子 / `Time.deltaTime` 驱动的插值。
  **不受影响**：`Time.unscaledTime` / `Time.realtimeSinceStartup` / `WaitForSecondsRealtime` / 编辑器自身的刷新。
  `timeScale = 0` 时画面照常渲染，只是逻辑与物理停住（Editor 的暂停按钮是另一回事，它连渲染一起停）。
- 配置在 **EditorPrefs**，所以换机器 / 换 Unity 账号就是另一套速度点；想清干净就删掉那个键。
