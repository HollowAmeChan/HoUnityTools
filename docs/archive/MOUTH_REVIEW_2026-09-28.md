**结构性不变式（这条最该写下来）**：嘴区域对**一根唇键**的最坏 `Σw = 5`（三个带门的孩子 + 倒V + 鼓嘴都写它）
⇒ 余项 `(1 − Σw)·默认值 = −4 × 默认值` ⇒ **"默认值 = 0"是这套架构的硬前提**（模型静息全 0）。
这就是"角点要不要写 0"真正该管的事：**default ≠ 0 的键，片段里写 0 也压不住**（`(1−Σw)·default` 那一项躲不掉）。
⇒ 建议验收加一条：跑一次"模型静息探针"，确认这些嘴键在进树时的值都是 0。

**"混合树以「动画」为处理对象，不是以「轨道」为对象"（2026-09-28 用户定稿的一句话）** ——
这一节的展开版已写进机制文档：`docs/BLEND_TREE_LIMITS.md` **§1.2**（作者必读）。要点：
>>>NEW
Unity 里**权重是每个孩子一份**（同一个孩子里所有曲线共用这一个权重）——既不是"每条轨道单独算"，也不是"按轨道预乘"；
⇒ 用户直觉里的"以动画的角度先预乘"**在表内就是事实** ✓。代入 `输出 = Σᵢ wᵢ·vᵢ + (1 − Σw)·默认值`：

* **表内（1D/2D）：`Σw` 恒为 1**（缺角时靠负权重也要维持 1）⇒ 余项 = 0 ⇒ **默认值根本不参与**
  ⇒ **"铺 0 轨道"与"不铺"完全等价** ✓（每格只写"这一格要起的那几根键"，0 轨道一根都不用铺）。
  只有一格写 1 时，那根键的曲线**就是那一格的权重曲线**；代价是**形状不可控**（1D 线性；2D 是 Unity 没公开的距离权重，实测偏差可达 6%）。
  ⚠️ 表内真正的风险是**表形状有洞 / 退化**时的**负权重**（Σw 必须凑成 1）⇒ 单写者的键会冲到 >1 或 <0，**引擎不夹取** ✗
  ⇒ 这正是"每个能到达的角都要摆姿势、别让点共线/重合"那条实测结论的来历。
* **跨区域（Direct 层，如嘴区域那 7 个孩子）：`Σw` 不归一**（最坏 5）⇒ 默认值会漏，而且是 `(1−Σw)·默认值 = −4×默认值`（甚至反号）
  ⇒ **默认值必须为 0**；两个活跃写者会**加权平均**（混合树没有后写覆盖）⇒ 要互斥只能用**门**，写 0 压不住。
⇒ 结论：**"每格把所有轴铺满"只在跨区域那一层才要小心，而且解法是门 + 默认值 0，不是写 0。**

**"删角"的判据（2026-09-28 用户提出；当天三处裁剪都用它复核过）**：
一个角点代表的**不是**"两根轴各自的量"，而是**"两者同时拉到 1"的那个姿势**（作者画的）。
删掉它 ⇒ 那个组合只能由邻点**凸组合（平均）**给出 —— 而 2D 混合是**姿势的凸组合，不是通道相加**
⇒ 对**不同的键**（左颊键 / 右颊键、blink / squint），50/50 混合 = **"两边各拉一半"**，**不等于"两边都拉满"** ✗。

| 删角**安全** | 删角**不安全** |
| --- | --- |
| ① 那根轴在那一档**到不了**（jaw 的"咬合 × 侧偏"：咬紧时侧偏只有 0.02~0.04；shift 的"上移 × 侧移"：噘嘴时嘴居中 ⇒ `Mouth/X` ≈ 0）**或** ② 那个组合在语义上就等于邻点的平均 | 那个角是**独立姿势** —— "两者同时拉满"的形状不是各自一半的和（**双鼓** / **睁大+眯** / 猫嘴 这类）⇒ **必须留格** |

对照当天三刀：**jaw 删 4 格** = ①（到不了，安全）· **shift 删 2 角** = ①（到不了；代价是那点输入被投影成"一半侧移 + 一半上移"）
· **`Cheek` 的双鼓角** = ②（独立姿势）⇒ **保留**（用户 2026-09-28 拍板保留整棵 `Cheek`）。
要"两者都到 1"又不想留角，唯一的替代是**在中间层把两根轴合成一根**（如 鼓嘴 = `max(左, 右)` 再用 1D 表），
让作者画"双鼓"那一档 —— 那也不是平均 ✓，但换不来"省格"。

**当天两处裁剪的"为什么"（用户 2026-09-28 追问后的定稿口径）**：

* **jaw 为什么可以降 1D**：下颌是**绕关节转**的 ⇒ 在（张开量 × 侧偏）平面上，**可达集本来是一条弧**
  （实测：咬紧 (≈0, 0.02~0.04) → 微张 (0.4, **0.52** 峰) → 张满 (0.75, 又变小)）⇒ **"上下 × 左右"的方格是虚构的**。
  要么沿这条弧做一条 1D，要么只留"上下"这一维（现在的选择）—— **1D 是更贴实物**，不只是省格子。
  （⚠️ 代价：中部那点"侧偏"信息整维丢弃 —— 这正是"到不了/不值得"的判据①在起作用。）
* **MouthShift 为什么保留双轴**：左右、上下**都是真实、独立、到得了的状态**（`mouthLeft/Right` 0.963~0.976）。
  压成 1D 就得**拆成两颗 1D 树**（3 + 3 = 6 格），代价：同一批位移键变成**两个写者**（`Σw = 2` ⇒ 余项 `−1×默认值`）、
  格子更多、两根轴各自平滑/门各自标。⇒ 两颗 1D **可行**（前提：那两棵树的片段只写位移键 + 默认值 = 0），
  但换不来省事 ⇒ 现在这张 **2D 4 格**是对的选择（斜向位移由对角格/投影给出，是真实状态）。
