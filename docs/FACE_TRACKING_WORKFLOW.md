# 面捕工作流

日期：2026-09-25。这份讲**怎么用**。现状一句话：**调试状态不往角色预制件上挂东西**（没有调试组件、
没有调试引用），一切从菜单
`HoUnityTools/面捕/` 下面那三个页进。

> ⚠️ **"角色预制件零组件"这条只约束"调试状态"**（2026-09-25 澄清）。**产品内容当然要挂在角色上** ——
> 例如动态参数 Hub（[动态参数](FACE_TRACKING_DYNAMIC_PARAMETERS.md)）就是角色 mod 自己挂的组件，
> 用户已确认"可以接受角色 mod 制作时挂新脚本"，而且带自定义脚本的角色 mod 打包是既有能力。

> ⚠️ **先读 [§2.1](#21-️-终点不是-arkit-形态键是动画)**：终点是**动画**，不是 ARKit 形态键；
> 现在这套 ARKit 映射是**过渡件**。"哪些轴成 2D 混合树"由作者按模型定，不是我们按 52 个名字推出来的。

## 0. 一句话

**面捕不接管角色的 Animator。** 它在一台**隐藏的影子层级**上跑一份面部控制器，
只把"我们拥有的那些形态键"抄回真实模型。身体的动画、Timeline、LookAt、别的约束全都照常。
状态不挂在角色上：调试设置落在 `Assets/HoFaceDebugSettings.json`，每帧由菜单宿主推。

## 1. 四段流水线

```
① 原始输入            ② 中间层（配置文件）              ③ 影子台                ④ 写回
VTS 手机 UDP     →   输入行：线名 → 规范名          →   会话把参数喂给      →   只写占用表里
（请求式，0..1）      （+ 曲线 + 有序修饰符）            影子上的那份控制器       自己拥有的形态键
                     输出行：参数名 = 曲线(表达式)
```

- ①**只交原样**：接收端给的是手机发来的线名与原始值（外加 `FaceFound` / 热键），
  改名、量纲换算、合并全在②。
- ②是**映射表的唯一来源**。面板把它当**必填总闸**（空着就锁住下面各栏），
  **留空 / 没指定配置文件 ⇒ 两类行都是空表，这一层不做事** —— **没有内置默认兜底**
  （2026-09-25 起与 Warudo 侧统一为"空 = 空表"；「开始驱动」也因此被 gate 住）。
  ⚠️ **2026-09-26 起连那份内置默认表本身也删了**：仓库里**不存在任何一份默认配置**，
  「新建」写出来的也是**空**表（见 [中间层 §6.1](FACE_TRACKING_MIDDLE_LAYER.md)）。
  **真正的语义在"指定之后"**：输入行**只认配置文件里的那一份** —— 漏了一条线名，那条链就静默失效；
  输出行也是同一句：那一类为空就是空表。
- ③跑的是你在工程里那份控制器（「控制器编辑」就地装配出来的）。
  哪些键算数由**你自己的树**决定 —— 我们不再注入"区域开关"这类门控。

## 2. 三个入口（菜单 `HoUnityTools/面捕/`）

| 页 | 回答什么 | 什么时候用 |
| --- | --- | --- |
| **调试面板** | 这台角色接到哪、现在收到什么、出问题在哪 | 日常：连接、看裸输入值、排查 |
| **控制器编辑** | 控制器里有什么、动画填上了没 | 换角色 / 换动画文件夹 / 换控制器时装配一次；**槽位片段默认就在控制器旁边的 `Animations/`**（骨架生成时每个槽位建一份空片段，文件名 = 槽位名），所以这一栏通常只需指过去看一眼 |
| **配置文件** | 线名怎么变成规范名、规范名怎么变成参数 | 改映射、量纲、曲线、修饰符 |

## 2.1 ⚠️ 终点不是 ARKit 形态键，是**动画**

这一段是**方向**，写在这里是因为它决定"现在做的哪些东西是过渡件"。用户 2026-09-25 明确：

> 我现在测试的模型还是用的 arkit 形态键，**最后肯定不是这一套了，最后实际上是做的动画了，动画才表示一个状态**。
> 这些动画也没有什么标准命名，**到底哪些要给成 2d 混合树**……我们初版甚至可以不做 arkit 的东西，
> 我之后把形态键做完了我们会再回来弄。

所以：

| | 状态 |
| --- | --- |
| **当前的 ARKit 那套**（52 个 `ARKit/<规范名>` 输出行、眼睑两条轴 —— 那是**已删的内置默认表** `HoFaceMiddlewareDefaults` 的形状，以前也随 `ho-vts-default.hoface.json` 发过，那份也删了；**2026-09-26 连这个类本身都删掉**，见 [中间层 §6.1](FACE_TRACKING_MIDDLE_LAYER.md)） | **过渡 / 测试件**。它是"形态键做完之前，能拿现成模型把整条链跑通"的桥，不是产品契约。⚠️ 现在发货的那份 `ho-iPhoneVTS.hoface.json` 出口**不写 `ARKit/*`**，而是**裸规范名**（G1）+ 合成 VTS 官方追踪参数（G2，见 [HO 参数规范](PARAMETER_HO.md)） |
| **终点** | 动画 = 状态。一个状态由一份动画表达，**动画之间没有标准命名**，**哪些轴成 2D 混合树由作者按模型决定**（见 [参数空间](VTS_FACE_PARAMETER_SPACES.md)：格数、方阵与否都留给作者） |
| **我们该做的** | 把**线名 → 规范名**那一侧（输入行、方言、量纲、曲线、滤波）做稳；输出那一侧是**接口**，等作者的树/动画定了再接 |
| **初版可以不做 ARKit 的东西** | 可以。于是 `控制器` 那条路（把作者的控制器 + 它的 rig 打进 bundle、运行时喂参数采形状）就是**主路径**，而不是"可选模式" |

**这对已经建好的东西意味着什么**（别推翻）：

- **不变**：输入行的方言映射/量纲/曲线/滤波、`Core/HoFaceChain.cs` 的求值、参数处理节点、
  控制器的打包与运行期求值（`HoFaceController`）、Warudo 那两个节点的接口形状。
- **要等作者定的**：输出行的**名字集合**（发货那份是 G1 裸规范名 + G2 官方 VTS 名，共 90 行；
  2026-09-27 起**另加 41 行控制器轴 `Ho/Drive/*`**，见 [HO 参数规范](PARAMETER_HO.md) §3.7）—— 等动画做完，
  输出行改成"规范名 → 作者参数名"，**两层之间的接口不变**（还是一份 `Dictionary<string,float>`）。
- **别做的事**：不要按 ARKit 的名字去推断"哪些轴该成 2D"、不要把 52 这个数字当制作规格、
  不要为 ARKit 名字写死任何映射（一个下划线错了就静默失效）。

## 3. 首次接线

| # | 做什么 | 在哪 |
| --- | --- | --- |
| 1 | VTS 手机版：第一页底部打开 **「3rd Party PC Clients」**（默认端口 21412） | 手机 App |
| 2 | 填**手机 IP** + 本机监听端口（Unity 调试面板默认 **49984**；⚠️ Warudo 节点的接收器默认是 **49985** —— 两边各管自己的默认，别以为其中一个是错的），点「连接」；3 秒没收到包就先点「授予权限」 | 调试面板「对象」栏 |
| 3 | 把场景里的角色拖进「调试对象」 —— **角色上不需要挂任何组件**，拿它只是为了读骨架与网格 | 同上 |
| 4 | 把包内**预置控制器目录**里的控制器复制一份到工程 → 拖进「控制器」栏 → 指「动画文件夹」→ **原地装配** | 控制器编辑 |
| 5 | 确认输入行里有你要用的线名（VTS 手机是 **PascalCase**：`JawOpen`、`EyeBlinkLeft`…）；**留空 = 空表、这一层不做事**（**没有内置默认兜底，也没有任何默认配置可退回**）。要新建就开「配置文件」窗口的「新建」—— 它写出来的是**空**配置（输入行 / 输出行都从零开始），映射得自己填 | 配置文件 |
| 6 | 进播放模式 → **开始驱动**（停止会把占用的键还回去） | 调试面板「对象」栏 |

之后：改配置 → 保存（会话自己重读，不用重开播放）；换动画 → 控制器编辑里再「原地装配」；
换角色 / 换控制器 → 在「对象」栏改，「开始驱动」会重新绑定。

## 4. 调试面板的四节

| 节 | 回答什么 | 里面有什么 |
| --- | --- | --- |
| **对象** | 接到哪 | 输入源（手机 IP + 端口 + 启用）、**控制器**、**配置文件**（必填总闸）、电脑 IPv4、调试对象；**最底下两行** = 布尔开关（**预览混合树** / **自动驱动** / **写动态参数** + 灰色的 `HoFaceSemanticHub` 目标）与功能按钮（**连接 / 断开** + **开始驱动 / 停止并交还**，居中）。「预览混合树」默认开：影子台 `Ho Face Shadow` 出现在 Hierarchy，选中它 + Animator 窗口 = 看运行中的那棵树与实时参数；「自动驱动」**默认开** = 进播放模式自动按下「开始驱动」（**不会**自动连手机） |
| **配置详情** | 这份配置吃啥、吐啥 | 输入行与输出行逐行摊开（只读：规范名 / 输出、曲线点数、修饰符链），解析器报的问题也在这 |
| **参数输入** | 手机上这一帧到底发了什么 | **全部裸线名**：值（0..1 画条）+ 距上帧秒数 + 筛选框；**纯调试读数**，不参与求值 |
| **排查**（默认收起，真出问题时自己弹开一次） | 收不到包 / 收到奇怪的包时看这里 | 防火墙状态与「授予权限」、包统计（包 / 无效 / 其他来源 / 丢旧帧 / 请求）、**姿态监视**（头姿 / 头位 / 左右眼）、输出绑定数 |

⚠️ 「参数输入」与「姿态监视」读的是**两样东西**：前者是手机原样线名，后者是**输入行算出来的规范值**
（量纲由你在配置里怎么换算决定）。姿态监视显示「—」= 这份配置没把那个名字映射过来。

## 5. 什么会写盘、什么不会

| 写盘 | 不写盘 |
| --- | --- |
| 「控制器编辑」的**原地装配**（改的是你工程里那份 `.controller`；GUID 不变） | 影子台上的临时 OverrideController、占用表、包统计 |
| 「配置文件」窗口的**保存**（写回那个 `.hoface.json`） | 面板上的筛选、折叠、画条 |
| 「配置文件」窗口的**「新建」**（写出来的是一份**空**配置，没有任何默认行） | 「参数输入」栏的读数 |
| 调试面板上改对象 / 端口 / IP / 时间常数（存 `Assets/HoFaceDebugSettings.json`） | 「授予权限」只动 Windows 防火墙规则 |
| 输入源列表（存 `UserSettings/HoUnityTools/FaceInput.asset`） | 通道的模式 / 手动值（过渡期字段，**目前面板上没有入口**） |

## 6. 排查清单

| 现象 | 先看哪 |
| --- | --- |
| 完全没反应 | 「对象」栏的连接状态 → 「排查」的包统计（`包 0`）→ 防火墙「已放行 / 未放行」；再确认手机与电脑同网段、Wi-Fi 没被蜂窝或 VPN 分流 |
| 收不到包，但显示「其他来源 N」 | 手机 IP 填错了 —— 排查区会直接告诉你包是从哪个地址来的，并给一个「改成这个地址」 |
| 显示「已断流」 | 看包统计里那个源的「距上帧」在不在涨：手机 App 退后台 / 锁屏、Wi-Fi 断了都会这样 |
| **包有、裸值在动，但脸不动** | ①「配置详情」里有没有你要的那一行**输入行**（VTS 线名是 PascalCase）；②那一行的规范名有没有被输出行吃掉；③控制器里到底有没有对应的参数（控制器编辑页的详情会列） |
| 某个键一直不动 | 控制器里那个槽位是不是「缺」（控制器编辑页的详情点名）；键在目标网格上不存在也会落不到任何地方 |
| 头姿 / 眼动那几行是「—」 | 这份配置没有把那个名字从线名映射过来（排查区的姿态监视读的是输入行的结果） |
| 断流后脸定格 | 断流回中性：`staleSeconds` / `neutralFadeSeconds`（面板上改，写进调试设置） |
| 和 LookAt 抢同一批键 | 两边只留一个写者。面捕只写**控制器里注册到的**那些键（占用表在会话里），LookAt 那边就别再写同样的键 |
| 停不下来 / 松手后不回基础表情 | 「停止并交还」会把占用的键还回去；如果这时还挂着**别的**写者（例如官方 iFacialMocap 那套图），那不是我们的账 |
