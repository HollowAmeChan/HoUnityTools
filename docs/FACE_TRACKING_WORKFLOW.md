# 面捕工作流

日期：2026-09-23。这份讲**怎么用**：从接到角色、到日常改配置、到排查。
讲"值是怎么被加工"的见 [面捕中间层处理](FACE_TRACKING_MIDDLE_LAYER.md)；
讲"哪些处理能放进混合树"见 [混合树的能力边界](BLEND_TREE_LIMITS.md)。

## 0. 一句话

**面捕不接管角色的 Animator。** 它在一条**隐藏的影子层级**上跑一份面部控制器，
只把"我们拥有的那些形态键"抄回真实模型。身体的动画、Timeline、LookAt、别的约束全都照常。

## 1. 四段流水线

```
① 原始输入            ② 参数生产（中间层）        ③ 门控                ④ 输出
iFacialMocap UDP  →   增益 / 死区 / 平滑 /     →  区域闸 + 键占用    →  写控制器参数
52 个 ARKit 通道      双眼同步 / 轴生产            （谁算数、谁让位）      + 影子求值后抄键回模型
```

影子台上跑的是**你装配出来的那份面部控制器**：它由**混合树模板**（树形）+ **动画文件夹**（姿势数据）
装配而成。控制器里有什么形状、吃什么参数，都由它们决定。**面捕只负责算参数值喂进去**；
树怎么编、格子怎么写，是模板作者与动画作者的事（见 [面捕控制器结构](FACE_TRACKING_CONTROLLER_STRUCTURE.md) §5）。

**两个作者侧的工具**（都不属于面捕本身）：

| 工具 | 在哪 | 干什么 |
| --- | --- | --- |
| 形态键基础动画 | 菜单 `HoUnityTools/形态键基础动画` | 给根物体 + 网格列表，每个形态键出一份 `<键名>.anim`（值 100 常量，一个片段写所有有这个键的网格）→ 直接扔进动画文件夹 |

## 2. 首次接线（六步）

| # | 做什么 | 在哪 |
| --- | --- | --- |
| 1 | 手机 iFacialMocap 填 PC 的 IPv4 + 端口 **49983**，开始发送 | 手机 App |
| 2 | 连接（必要时点「放行防火墙」） | 全局连接面板 |
| 3 | 角色上挂 `HoFaceTrackingDebugger`，填**角色 Animator** | 组件 Inspector「接线」 |
| 4 | 在「初始化」里选**混合树模板**、指一个**动画文件夹**（没有就先用上面那个工具生成一份）、点「按 Animator 填充」拿到**驱动对象**，看折叠框「动画填充」确认槽位，再点**装配控制器** | 同上 |
| 5 | 点**检查绑定** —— 键名/层级路径对不上时，这里会列出来 | 同上 |
| 6 | 进播放模式 → **开始驱动** | 同上 |

之后换模板 / 换文件夹 / 换驱动对象，都还是那一个按钮（**重新装配**）：重来一遍，GUID 不变。

## 3. 面板的五个分区

栏名就是标题，**不带序号** —— 序号只会让人以为有先后顺序，实际五栏没有顺序关系。

| 分区 | 回答什么 | 里面有什么 | 改完要不要重建 |
| --- | --- | --- | --- |
| 接线 | 这台组件接到哪 | 角色 / 控制器 / 自动驱动 + 全局面板、开始驱动 | 不写盘 |
| 初始化 | **模板 + 文件夹 + 驱动哪些网格** | 混合树模板 / 动画文件夹 / 驱动对象列表 / 折叠框「动画填充」/ 装配控制器 / 检查绑定 / 定位资产 | 装配写盘 |
| 控制器输出参数设置 | **什么**被写出去、什么时候让位 | 眼/唇/凝视三个闸、控制器结构（从资产读的实况）、断流等待、回中性 | 不写盘（结构要去编那份模板） |
| 参数生产 | **值怎么被加工** | 分组平滑、分组死区、眼睑三档、配比 | 立即生效（纯运行时） |
| 输入参数 | 每一路输入怎么来 | 52 行：形状键 / 参数 / 模式 / 滑杆 / 增益 / 中性 | 立即生效 |

**折叠只有一层**，每栏内部只用 box 分块；「动画填充」是栏内的行内折叠，不算第二层。

## 4. 什么会写盘、什么不会

| 写盘（点按钮才发生） | 不写盘（运行时的） |
| --- | --- |
| 装配控制器：把模板**整份**搬成这台角色的控制器，并填入动画文件夹里的片段（覆盖时 GUID 不变） | 面板上的所有调参（平滑/死区/模式/增益/中性） |
| 形态键基础动画：往你指定的文件夹里产出/覆盖 `<键名>.anim` | 影子台上的 OverrideController（内存里的） |
| （编模板本身 —— 在混合树编辑器里改那份模板） | 被占用的形态键、预览滑条 |
| | 「动画填充」折叠框只是读，不写 |

## 5. 排查清单

| 现象 | 先看哪 |
| --- | --- |
| 完全没反应 | 「控制器输出参数设置」的断流等待 / 全局面板的包速率 / 防火墙放行；组件是否在播放模式且已「开始驱动」 |
| 找不到键 | 点「检查绑定」；「输入参数」里该行的键名解析状态；「控制器输出参数设置」的「控制器结构」会列出**模型上没有、因而落不到任何网格上**的键 —— 那些格子要去模型上补形态键，或者在模板里改掉 |
| **某个动作完全没反应** | 「初始化」栏的「动画填充」折叠框：那个槽位是不是"缺"（文件夹里没有、模板自带的片段也没写键） |
| **只有一只眼眨** | 「参数生产」的「眼睑」档位选成了**单键双眼** —— 它只驱动一侧，只适用于"左右键各自都能闭双眼"的模型。**左右键各管一只眼时选「左右独立」** |
| **不能 wink** | 「参数生产」的「眼睑」档位不是「左右独立」（「强制同眨」按定义就是两眼一起动） |
| **过眨眼** | 眼睑是否被并成 2D 树（见中间层文档 §5，「控制器输出参数设置」里那行「控制器结构」会告诉你实际形状）。若模型上左右键各管一只眼，「参数生产」的眼睑档位该是「左右独立」 |
| 静止时抖 | 「参数生产」的分组死区（压掉低幅噪声） |
| 追不上 / 太黏 | 「参数生产」的分组平滑（0 = 直通；眼球要跟得紧、嘴更黏） |
| 和 LookAt 抢眼球 | 「控制器输出参数设置」的「凝视形态键」闸：**两边只留一个** |
| 断流后脸僵住 | 「控制器输出参数设置」的断流等待 / 回中性 |
