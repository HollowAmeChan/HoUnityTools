# 面捕工作流

日期：2026-09-23。这份讲**怎么用**：从接到角色、到日常改配置、到排查。
讲"值是怎么被加工"的见 [面捕中间层处理](FACE_TRACKING_MIDDLE_LAYER.md)；
讲"哪些处理能放进混合树"见 [混合树的能力边界](BLEND_TREE_LIMITS.md)。

## 0. 一句话

**面捕不接管角色的 Animator。** 它在一条**隐藏的影子层级**上跑一份面部控制器，
只把"我们拥有的那些形态键"抄回真实模型。身体的动画、Timeline、LookAt、别的约束全都照常。

## 1. 四段流水线

```
① 原始输入            ② 参数生产（中间层）        ③ 门控                ④ 输出
iFacialMocap UDP  →   增益 / 死区 / 平滑 /     →  区域闸 + 键占用    →  写控制器参数
52 个 ARKit 通道      双眼同步 / 轴生产            （谁算数、谁让位）      + 影子求值后抄键回模型
```

影子台上的控制器是**用户自己的资产**：`Ho/00 Drive` 那棵驱动树是我们生成的，
`Ho/99 (EDIT THIS)` 那一段是留给用户加逻辑的。**混合树由用户自己编**，我们只提供底子和基础件。

## 2. 首次接线（六步）

| # | 做什么 | 在哪 |
| --- | --- | --- |
| 1 | 手机 iFacialMocap 填 PC 的 IPv4 + 端口 **49983**，开始发送 | 手机 App |
| 2 | 连接（必要时点「放行防火墙」） | 全局连接面板 |
| 3 | 角色上挂 `HoFaceTrackingDebugger`，填**角色 Animator** 与**面部控制器** | 组件 Inspector ① 接线 |
| 4 | 点**初始化控制器** —— 产出一个完整文件（含驱动层 + 扩展点） | 同上 |
| 5 | 点**检查绑定** —— 键名/层级路径对不上时，这里会列出来 | 同上 |
| 6 | 进播放模式 → **开始驱动** | 同上 |

之后日常改配置**不再需要第 4 步**：改完面板点**应用改动**（就地手术，只重写 `Ho/` 段）。

## 3. 面板的四个分区

| 分区 | 回答什么 | 里面有什么 | 改完要不要重建 |
| --- | --- | --- | --- |
| ① 接线 | 接到哪、以及那几个会写盘的动作 | 角色/控制器/自动驱动 + 五个按钮 | 初始化才写盘 |
| ② 控制器输出参数设置 | **什么**被写出去、什么时候让位 | 眼/唇/凝视三个闸、断流等待、回中性、路径重映射 | 应用改动 |
| ③ 参数生产 | **值怎么被加工** | 分组平滑、分组死区、双眼同步、单键双眼 | 立即生效（纯运行时） |
| ④ 输入参数 | 每一路输入怎么来 | 52 行：形状键 / 参数 / 模式 / 滑杆 / 增益 / 中性 | 立即生效 |

**折叠只有一层**，每栏内部只用 box 分块。

## 4. 什么会写盘、什么不会

| 写盘（点按钮才发生） | 不写盘（运行时的） |
| --- | --- |
| 初始化控制器：产出/覆盖**整个文件** | 面板上的所有调参（平滑/死区/模式/增益/中性） |
| 应用改动：只重写 `Ho/00 Drive` 那一段 | 影子台上的 OverrideController（内存里的） |
| （用户手工编混合树） | 被占用的形态键、预览滑条 |

## 5. 排查清单

| 现象 | 先看哪 |
| --- | --- |
| 完全没反应 | ② 的断流等待 / 全局面板的包速率 / 防火墙放行；组件是否在播放模式且已「开始驱动」 |
| 找不到键 | 点「检查绑定」；④ 里该行的键名解析状态；模型层级是否和控制器路径一致（不一致用②里的路径重映射） |
| **只有一只眼眨** | ③ 的「单键双眼」开着 —— 它只驱动一侧，只适用于"左右键各自都能闭双眼"的模型。**左右键各管一只眼时关掉** |
| **过眨眼** | 眼睑是否被并成 2D 树（blink/wide/squint 进同一棵树；见中间层文档 §5）。若模型上左右键各管一只眼，③ 的两个同步开关都该关 |
| 静止时抖 | ③ 的分组死区（压掉低幅噪声） |
| 追不上 / 太黏 | ③ 的分组平滑（0 = 直通；眼球要跟得紧、嘴更黏） |
| 和 LookAt 抢眼球 | ② 的「凝视形态键」闸：**两边只留一个** |
| 断流后脸僵住 | ② 的断流等待 / 回中性 |
