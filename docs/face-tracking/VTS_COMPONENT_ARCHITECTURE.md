# VTS 角色组件架构（新规划）

规划日期：2026-10-29

这份文档取代旧的“参数处理节点 → HoFace 控制求解节点 → AssetBundle 影子 Animator”路线，作为后续实现依据。旧代码和旧文档暂时保留作迁移和历史参考，迁移完成后再归档或删除。

## 1. 最终目标

面捕运行时属于角色本身。角色预制件带着自己的面捕组件、规则和控制器；外部系统只负责提供输入。

~~~
输入来源
    ↓
输入适配器
    ↓ 原始完整字典
HoFaceVTS参数标定（Warudo 节点侧）
    ↓ 标定后的完整字典
角色预制件上的 HoVtsParameterReceiver
    ├─ 中间层表达式 / 曲线 / 修饰符
    ├─ HoVtsController → 角色表情控制器
    └─ HoVtsLookAt → 独立 IK / 头部与眼球姿态
~~~

组件不带 Warudo 名称，因为同一套角色组件也应能被 Unity 调试、其他输入适配器和未来的其他运行环境使用。

## 2. 角色组件

组件挂在角色预制件中的空物体上，由角色作者显式放置。

### HoVtsParameterReceiver

这是 VTS 参数中枢，不是平台专用 Hub。

它负责接收已经由输入标定节点处理的完整 VTS 字典、追踪状态和时间，保存原始值和处理后值，执行中间层规则，并为控制器和 LookAt 组件提供同一份数据。

核心接口语义接近：

~~~csharp
ApplyRawFrame(Dictionary<string, float> values, bool tracked, double timestamp);
bool TryGet(string name, out float value);
float Get(string name, float fallback = 0f);
bool Tracked { get; }
~~~

一个角色一份中枢，多个角色互不串线。中枢不使用静态全局状态。其他角色组件显式引用这个中枢来读参；它只提供 VTS 系统的数据，不恢复通用任意参数写入平台。

中间层规则和控制器引用由角色组件持有，并随角色打包。现有 JSON 表达式、曲线、有序修饰符和逐行依赖语义继续使用；JSON 可作为作者侧导入、导出和编辑格式，不再是 Warudo 插件沙箱中的必填运行配置。组件具体采用序列化规则数据还是可打包的文本资源，实施时核对序列化与 UMod 行为后确定，不改变角色持有规则这一边界。

参数中枢区分输入字典与中间层输出，读取接口需要明确读哪一层。同一帧只求值一次，多消费者不能让平滑和维持计时重复推进。输入标定留在组件之外；组件不再提供一套独立的输入范围或倍率标定。

### HoVtsController

它读取参数中枢的处理后参数，运行角色预制件中引用的控制器，并把结果写到角色拥有的形态键和控制器负责的骨骼。控制器不从外部沙箱加载，不从节点输入 Bundle 文件名，也不由蓝图选择。

不能依赖 Warudo 会禁用的角色原有 Animator 自动播放。组件需要验证独立的手动求值机制，例如独立求值对象或 PlayableGraph；具体实现尚未定案，不能提前保证只建一个 Animator 就能工作。内部隔离求值仍可作为实现方案，但不再由插件节点加载 Bundle、克隆整套角色并通过官方表情写入节点绕一圈。

控制器负责表情姿势；头眼注视与根位置属于另一条职责。控制器若有骨骼曲线，只写作者明确交给它的骨骼，不与 HoVtsLookAt 或官方姿态节点重复写入。

### HoVtsLookAt

它独立读取参数中枢和角色目标，直接执行头部与眼球的 LookAt / IK。不经过面部 AnimatorController，也不依赖某个平台的官方 LookAt 节点。

## 3. 输入适配器

Warudo 网络接收节点与参数标定节点保留：接收器只交出原始字典和新鲜度，标定只处理输入范围、倍率和最终输出范围。中间层运算迁入角色组件，不迁入标定节点。

~~~text
HoFaceVTS接收器 → HoFaceVTS参数标定 → 角色输入桥接 → HoVtsParameterReceiver
                                 └→ 现有姿态适配 → 官方姿态节点（可选）
~~~

标定后的数据应由明确的桥接入口写入目标角色。桥接可以是标定节点的目标角色接口或独立薄写入节点，具体数量在实施时确定；不能声称网络接收器既只交原始值，又能越过标定节点直接写入角色。桥接只查找组件、交付字典与追踪状态，不运行规则或控制器，不自动给角色添加组件。

输入必须覆盖完整 VTS 字典，而不只包含 ARKit 形状。当前 iPhone 实测字段为 52 个形状、12 个头/眼姿态分量及 FaceFound、Hotkey、Timestamp；未知自定义键不因固定标定表而丢失。头姿和位移不能统一压成 0～1；FaceFound、Hotkey、Timestamp 原样透传，不做连续标定。新鲜度与 FaceFound 一起决定追踪状态，不能仅凭字典非空判断有脸。时间行为使用单调本地时钟，不能把已转为 float 的协议 Timestamp 当精确计时器。

标定值保留在 Warudo 蓝图中，同一角色换设备时无需重打角色 Mod。Unity 调试可以直接喂原始数据或接输入侧标定；不向角色组件另存一份标定配置。

组件保持平台无关。未来其他环境通过适配器提供符合 VTS 字典约定的数据，不把新协议的解析或 Warudo API 耦合进角色组件。

## 4. 官方姿态节点

官方的头部旋转、LookAt、根位置、平滑和丢追节点是长期并行使用的外部系统，不是临时兼容方案。它们与 HoVtsController、HoVtsLookAt 通过不同的输出职责协作，不需要把官方节点迁入角色组件，也不需要为了自建系统而删除它们。

输入标定后的姿态字典经现有姿态适配节点转换为官方所需的骨骼数组和向量后，可以继续接官方姿态链：

~~~
完整 VTS 姿态参数
    → 姿态适配节点（字典转骨骼数组 / 向量）
    → 官方平滑 / 丢追处理
    → 官方 LookAt
    → 官方骨骼旋转偏移 / 根位置写入
~~~

我们的角色组件负责角色自身的表情控制器和自有 LookAt；官方节点可以继续接收标定后的 VTS 姿态字典。两套系统不能同时写同一组骨骼或根位，通过各自开关和目标范围明确唯一写者。无需为官方链新增迁移层、替代期限或强制 A/B 任务。HoVtsLookAt 可独立使用，官方节点也可继续使用。

头部位置不等于角色根位置。当前姿态适配节点不包含官方接收器内部的身体 IK，不得宣称已有等价的全身跟随。位置量纲、校准零点、根位参考空间都需验证；本规划不预设任何未经实测的换算倍率。

## 5. Unity 调试

Unity 调试面板不再让用户填写控制器、规则文件、动画文件夹或影子控制器。面板只需要调试对象、输入连接、连接 / 断开、自动开始 / 停止以及原始输入和组件状态观察。

选择调试对象后，面板自动在对象及子层级查找 HoVtsParameterReceiver；控制器和 LookAt 从角色已配置的组件引用读取。缺少组件时显示缺失，多份中枢时指出歧义，不偷偷新增组件，也不任意选择第一份。

面板把输入帧送进角色参数中枢，与 Warudo 运行共享规则执行和控制器后端。调试界面不再维护第二份控制器或规则。角色未配置 LookAt 时仍可调试表情；不强迫角色必须挂齐所有可选消费者。

保留现有三段观察（接收器原始值 / 规则输入 / 规则输出）、手动覆盖、时序录样、单区隔离和逐帧诊断。简化的是配置入口，不能砍掉已验证有效的分析工具。覆盖只存在于调试会话，不反写角色规则；停止调试时解除覆盖并交还写入对象。

规则编辑窗口改为编辑组件持有的规则，或导入/导出 JSON；配置编辑需要 Undo、显式保存和可恢复备份。控制器、动画部件制作和手调状态点仍是作者工具职责，本轮不改变已有公式和动画。

## 6. 被取代的旧设计

以下路线被新规划取代，后续不再扩展：

- HoFace控制求解 节点及其 Bundle 加载、影子反算和官方表情应用出口；
- HoFace参数处理 节点：表达式、曲线和修饰符迁入参数中枢；
- 外部控制器 AssetBundle；
- HoFT 控制器到 AssetBundle 打包页；
- 节点上选择控制器 Bundle 文件；
- 插件侧独立克隆角色反算控制器的部署路线；角色组件内部采用何种隔离求值方式仍需验证；
- Unity 调试面板单独输入控制器和中间层配置；
- 将中间层规则拆在节点和角色之外的两套运行时配置中。输入标定仍然保留在 Warudo 节点侧，这是有意的例外。

这些文件暂时保留用于迁移。新组件完成后，再将旧节点、旧页面、旧文档和旧验证工具移动到 docs/archive 或删除。

旧 HoFaceSemanticHub 的面捕动态参数职责由 HoVtsParameterReceiver 收拢，相关面捕专用写入路径纳入迁移清单。现有其他使用者不能未经核对直接删掉。新中枢不要求控制器通过状态机行为反写参数，不恢复已经否掉的动画槽位表和 Connector 方案。

本次只记录迁移目标：不删除旧节点、官方节点、角色文件或用户蓝图，不改 JSON 公式和资源 GUID。后续删除前列清每个旧入口的替代落点，并完成角色端运行验证。

## 7. 命名和打包规范

三个运行时组件的完整类型名固定为：

~~~
Hollow.HoUnityTools.FaceTracking.HoVtsParameterReceiver
Hollow.HoUnityTools.FaceTracking.HoVtsController
Hollow.HoUnityTools.FaceTracking.HoVtsLookAt
~~~

统一约定：

- Ho 前缀 + Vts 输入协议边界 + PascalCase 职责；
- 运行时代码放在运行时程序集，不能放在 Editor；
- 使用 DisallowMultipleComponent；
- 使用空的 AddComponentMenu，由角色预制件显式挂载；
- 不使用 Node、AssetBundle、SolverNode 作为组件名称；
- FastBuild 按完整类型名扫描组件并收集运行时源码闭包；
- FastBuild 组件说明和依赖映射登记三个完整类型；
- 按用户要求把新组件及依赖纳入 Mod 打包支持范围；FastBuild 当前通过预制件扫描、源码闭包、默认勾选和排除规则实现，不假设存在一张尚未找到的单独类型白名单；
- UMod lint 是禁止 API 的静态检查，不是组件白名单；两者分别验证；
- 运行时规则不能依赖 UnityEditor、磁盘路径读取或反射；角色组件不引用 Warudo 程序集；
- Plugin Mod 与 Character Mod 各自编译，完整类型名相同也不代表跨 Mod 类型相同。桥接方式须验证，不能把组件复制进插件后直接强转，也不能用被 UMod 禁止的反射兜底；
- 角色预制件、组件、规则和控制器在同一个 Mod 资产边界内验证。

## 8. 实施顺序

1. 固定 HoVtsParameterReceiver 的序列化字段、规则归属和输入/输出读取接口，先验证跨 Mod 参数桥接及运行时控制器求值。
2. 将现有中间层执行器迁入组件，保证 Unity 与运行时使用同一套语义。
3. 将控制器求值从 HoFace控制求解 迁入 HoVtsController。
4. 将已有 LookAt 约束改成 HoVtsLookAt 的 VTS 输入版本。
5. 保留网络接收和标定节点，实现标定后字典到角色中枢的桥接；现有姿态适配和官方链按需保留。
6. 改造 Unity 调试面板，自动查找角色组件，并使用组件内的中间层规则。
7. 迁移 WTD 角色预制件，确认组件、控制器、动画和规则随角色打包。
8. 删除 HoFT 页面、控制求解节点、旧参数处理节点及旧验证入口；官方姿态节点继续保留。

## 9. 验收标准

- 角色参数中枢和已配置的消费者独立工作，LookAt 可选；外部只需交付标定后的 VTS 帧；
- 多个角色同时运行时参数和控制器状态互不串线；
- 角色不依赖外部控制器 Bundle；
- 蓝图不再选择控制器、不再填写规则文件；
- Unity 调试和运行时使用同一份组件规则和同一套求值语义；
- VTS 断流时形态键、骨骼和 LookAt 都有明确恢复行为；
- FastBuild 产物中三个组件没有 Missing Script，UMod 编译和安全检查通过；
- 官方姿态链可独立保留，自有 LookAt 不与其抢同一批骨骼；无需以替换官方链为完成条件；
- 完整姿态和信号未因形状表过滤而丢失，断流、缺键和多消费者时域行为通过回归；
- Unity 调试只选对象即可取得组件规则与控制器，三段读数、覆盖和录样能力保留；
- 新系统完成后，旧 HoFT Bundle 和 HoFace 控制求解路线不再出现在活文档入口中。

## 10. 当前状态

本文是架构规划，列出的接口是语义草案，不代表整套组件、桥接或打包支持已经实现。第一步的 `HoVtsParameterReceiver` 运行时边界已经落地：它能按角色实例保存原始字典、处理后字典、追踪状态、时间和来源，并提供按名字读取与复制接口。第二步已接入包内 `HoVtsRuleEvaluator`，收到一帧后按角色组件持有的 `HoFaceMiddleware` 规则求值并写入处理后表；它仍未接入控制器和 LookAt。

FastBuild 已登记三个 `HoVts*` 完整类型名的组件说明，确保后续组件可以按角色 Mod 的源码闭包打包；目前只有参数中枢组件存在。HoVtsController、HoVtsLookAt、输入桥接和 Unity 面板迁移仍未实现。当前仓库中的 HoFT 页面、HoFace 控制求解节点、参数处理节点和影子控制器仍属于旧实现，按本文分阶段迁移。
