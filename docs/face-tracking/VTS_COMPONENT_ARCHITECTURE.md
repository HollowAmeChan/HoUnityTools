# VTS 角色组件架构（新规划）

规划日期：2026-10-29

这份文档取代旧的“参数处理节点 → HoFace 控制求解节点 → AssetBundle 影子 Animator”路线，作为后续实现依据。旧代码和旧文档暂时保留作迁移和历史参考，迁移完成后再归档或删除。

## 1. 最终目标

面捕运行时属于角色本身。角色预制件带着自己的面捕组件、规则和控制器；外部系统只负责提供输入。

~~~
输入来源
    ↓
输入适配器
    ↓ 原始完整字典
HoFaceVTS参数标定（Warudo 节点侧）
    ↓ 标定后的完整字典
角色预制件上的 HoVtsParameterReceiver
    ├─ 中间层表达式 / 曲线 / 修饰符
    ├─ HoVtsController → 角色表情控制器
    └─ HoVtsLookAt → 独立 IK / 头部与眼球姿态
~~~

组件不带 Warudo 名称，因为同一套角色组件也应能被 Unity 调试、其他输入适配器和未来的其他运行环境使用。

## 2. 角色组件

组件挂在角色预制件中的空物体上，由角色作者显式放置。

### HoVtsParameterReceiver

这是 VTS 参数中枢，不是平台专用 Hub。

它负责接收已经由输入标定节点处理的完整 VTS 字典、追踪状态和时间，保存原始值和处理后值，执行中间层规则，并为控制器和 LookAt 组件提供同一份数据。

核心接口语义接近：

~~~csharp
ApplyRawFrame(Dictionary<string, float> values, bool tracked, double timestamp);
bool TryGet(string name, out float value);
float Get(string name, float fallback = 0f);
bool Tracked { get; }
~~~

一个角色一份中枢，多个角色互不串线。中枢不使用静态全局状态。其他角色组件显式引用这个中枢来读参；它只提供 VTS 系统的数据，不恢复通用任意参数写入平台。

中间层规则和控制器引用由角色组件持有，并随角色打包。规则的事实来源是组件引用的 `.hoface.json` `TextAsset`：JSON 可以独立编辑、由 AI 直接修改、在多个角色之间复用，也可以在面板里快速切换引用。运行时只解析组件当前引用的文件；旧组件的内嵌表只作为迁移兜底，新角色不再把规则拷贝进组件。

参数中枢区分输入字典与中间层输出，读取接口需要明确读哪一层。同一帧只求值一次，多消费者不能让平滑和维持计时重复推进。输入标定留在组件之外；组件不再提供一套独立的输入范围或倍率标定。

接收器的输入超时默认为 1 秒，可由角色作者调整。没有新包时，组件在 LateUpdate 继续推进平滑、延迟和维持；适配器已在这一 Unity 帧求值时不再自动重复推进。读取参数本身不推进时间。最后收到输入的时刻与最后求值时刻分开保存，因此继续求值不会把断流误当成新包。超过超时后保留原始快照用于排查，处理后参数回到规则中性值，姿态消费者回中性；主动释放输入则交还写入对象。

运行时适配器的 timestamp 使用 Time.realtimeSinceStartupAsDouble，与组件自动时钟保持同一原点。离线宿主可显式 Tick(now)，但输入和求值必须使用同一个单调时钟；旧于最近求值的输入被拒绝，同一时刻不重复推进。网络接收线程的 Stopwatch 时间只用于输入侧判新鲜，不能直接作为组件时钟。

### HoVtsController

它读取参数中枢的处理后参数，运行角色预制件中引用的控制器，并把结果写到角色拥有的形态键和控制器负责的骨骼。控制器不从外部沙箱加载，不从节点输入 Bundle 文件名，也不由蓝图选择。

不能依赖 Warudo 会禁用的角色原有 Animator 自动播放。当前实现为独立空物体上的控制器槽，由手动 PlayableGraph 求值；隐藏求值对象只创建动画需要的 Transform 和形态键代理，不克隆整套角色，也不复制角色脚本。角色原有 Animator 的启用状态和控制器引用不变。

挂载方式：角色下建立空物体（例如 VTS），在上面挂 HoVtsController，指定参数接收器、动画控制器与输出根物体。动画路径相对于输出根物体解析，通常使用原来动画绑定的角色根物体；空物体本身不需要 Animator。组件引用的 RuntimeAnimatorController 直接随角色打包，不导出独立 Bundle。

编辑器读取控制器的动画曲线，将拥有的路径和属性保存在组件中。修改引用、点击“刷新动画绑定”、进入播放模式或 FastBuild 导出副本时更新绑定。运行时只写这些明确的形态键、位移/缩放轴和旋转属性，动画明确写出的零值同样生效。未提供的控制器参数使用资产声明的默认值；字典不触发 Trigger。停用组件、停用参数接收器或解除引用时，释放求值对象并恢复接管前的属性值。

面部求值支持形态键与 Transform 曲线。Humanoid 肌肉、对象引用、其他组件属性曲线在准备绑定时明确报错，避免打包后静默缺失。无追踪帧和输入超时均回到规则中性值，主动释放输入交还属性。

控制器负责表情姿势；头眼注视与根位置属于另一条职责。控制器若有骨骼曲线，只写作者明确交给它的骨骼，不与 HoVtsLookAt 或官方姿态节点重复写入。

### HoVtsLookAt

它独立读取参数中枢，直接约束头部与眼球的旋转。不经过面部 AnimatorController，不需要 Animator、Humanoid Avatar 或 OnAnimatorIK 回调，也不依赖某个平台的官方 LookAt 节点。当前实现针对 VTS 已经给出的姿态角度，不包含全身 IK 或头位到根位的推算。

空物体上挂 HoVtsLookAt，指定同一份接收器、姿态参考物体以及需要控制的头部/左右眼骨骼。参考物体通常是角色根物体，旋转使用它的坐标轴，避免假定各个模型的骨骼轴向相同。头部和双眼可分别关闭，以便将对应范围交给官方链。

只读取中枢的 JSON 规则输出：Rotation_x/y/z、EyeLeft_x/y/z、EyeRight_x/y/z。规则需发布同名姿态键；不读取 raw，不从 ARKit 形态键列表推测头眼姿态，也不在两层之间回退。输入增益、角度范围仍由外部输入标定处理。

姿态平滑为 0 时直通；大于 0 时按秒平滑，丢追后使用相同平滑回到中性姿态。追踪仍有效但姿态三轴不完整时，保持该骨骼最后一份完整旋转。释放输入或停用组件时交还骨骼；若外部系统已经写入更新的姿势，释放不会撤销它。此组件不写位置、缩放或形态键。

当前设备实测姿态轴为：头部 `Rotation_x` 左右转、`Rotation_y` 点头、`Rotation_z` 歪头；眼球 x/y 分量为水平/垂直转动。组件支持按 `Spine → Chest → UpperChest` 分布的上身低权重跟随，用于模拟 Live2D 式摆动。编辑器会显示参考轴、实际骨骼前方和 VTS 目标前方的 Gizmo。

## 3. 输入适配器

Warudo 网络接收节点与参数标定节点保留：接收器只交出原始字典和新鲜度，标定只处理输入范围、倍率和最终输出范围。中间层运算迁入角色组件，不迁入标定节点。

**2026-10-31 镜像轴约定与验证：**当前 WTD 使用的 ARKit 直通 JSON 将 `Rotation_x/y/z` 原名输出，LookAt 将 x 解释为水平转头、y 解释为上下点头、z 解释为歪头。接收器镜像必须反转 `Rotation_x`，保留 `Rotation_y`，不能再按 Unity 欧拉分量名直接反转 y。水平位移与眼球水平角反向、左右眼及左右形态键互换的处理保留。处理顺序为：接收器镜像/灵敏度/同眨 → 标定节点的中性姿态校准与范围倍率 → 角色 JSON → 消费组件。镜像开关切换时，中性偏移和采样中的累计值也同步镜像。

Unity 的 `Quaternion.eulerAngles` 返回 pitch/yaw/roll，而上述 VTS 字段为 yaw/pitch/roll；校准回写需要 x 取 Euler.y、y 取 Euler.x，眼球 y 还需恢复其原有反号。Unity 调试与 Warudo 的校准保持相同约定。包内 ARKit 模板与 WTD 的姿态输出同样直通，姿态曲线使用 ±180 恒等范围，而非 ARKit 表情的 0–1。`Tests~/VtsComponents/RunMirror.ps1` 在隔离工程中使用实际解析、接收、校准、JSON、标定数学及 LookAt 源码，通过真实 Unity 骨骼验证正负转头、点头、混合姿态及实时镜像切换；旧的 y 轴镜像会被回归测试拒绝。

~~~text
HoFaceVTS接收器 → HoFaceVTS参数标定 → 角色输入桥接 → HoVtsParameterReceiver
                                 └→ 现有姿态适配 → 官方姿态节点（可选）
~~~

标定后的数据应由明确的桥接入口写入目标角色。桥接可以是标定节点的目标角色接口或独立薄写入节点，具体数量在实施时确定；不能声称网络接收器既只交原始值，又能越过标定节点直接写入角色。桥接只查找组件、交付字典与追踪状态，不运行规则或控制器，不自动给角色添加组件。

目前实现为独立的“HoVTS角色输入”节点：角色选择 CharacterAsset，标定节点的“标定后原始值”接同名输入，网络接收节点的“新鲜”接“输入新鲜”。插件每帧调用隐藏执行入口，以 Warudo 的正常依赖求值拉取上游，无需再接一条可见执行线或连接状态输出。蓝图停用、节点销毁、切换角色、插件卸载时释放旧输入。

跨 Mod 使用 Unity 消息交付：先以 HoVtsFindReceiver 查询当前角色层级的启用接收器，恰好一份时才发送 HoVtsReceiveFrame。消息仅包含 Dictionary<string,float>、bool、double、string 和 Action<GameObject>，不共享自定义组件或 DTO 类型，也不调用 System.Reflection。角色同步复制字典、执行自己的规则并确认接收。多份接收器报歧义，不任取第一份。释放消息带来源标记，旧来源不能清掉其他来源已经写入的帧。

输入必须覆盖完整 VTS 字典，而不只包含 ARKit 形状。当前 iPhone 实测字段为 52 个形状、12 个头/眼姿态分量及 FaceFound、Hotkey、Timestamp；未知自定义键不因固定标定表而丢失。头姿和位移不能统一压成 0～1；FaceFound、Hotkey、Timestamp 原样透传，不做连续标定。新鲜度与 FaceFound 一起决定追踪状态，不能仅凭字典非空判断有脸。时间行为使用单调本地时钟，不能把已转为 float 的协议 Timestamp 当精确计时器。

标定值保留在 Warudo 蓝图中，同一角色换设备时无需重打角色 Mod。Unity 调试可以直接喂原始数据或接输入侧标定；不向角色组件另存一份标定配置。

输入侧还提供独立的三秒姿态中性校准入口：Warudo 接收器节点和 Unity 面捕调试面板都能启动采样，完成后对头部旋转、头位和双眼姿态扣除当前中性偏移。它不修改表情形态键、角色规则 JSON 或输入范围/倍率配置。

组件保持平台无关。未来其他环境通过适配器提供符合 VTS 字典约定的数据，不把新协议的解析或 Warudo API 耦合进角色组件。

## 4. 官方姿态节点

官方的头部旋转、LookAt、根位置、平滑和丢追节点是长期并行使用的外部系统，不是临时兼容方案。它们与 HoVtsController、HoVtsLookAt 通过不同的输出职责协作，不需要把官方节点迁入角色组件，也不需要为了自建系统而删除它们。

如果用户需要继续使用官方姿态链，可以自行把标定后的姿态字典接入已有官方适配方案；这不是 HoFaceTracking 正式主链的一部分：

~~~
完整 VTS 姿态参数
    → 姿态适配节点（字典转骨骼数组 / 向量）
    → 官方平滑 / 丢追处理
    → 官方 LookAt
    → 官方骨骼旋转偏移 / 根位置写入
~~~

正式主链只有接收器、参数标定和 HoVTS 角色输入；角色组件自己读取完整姿态字典并负责表情和自有 LookAt。官方节点可以作为外部兼容方案继续使用，但两套系统不能同时写同一组骨骼或根位。

头部位置不等于角色根位置。当前姿态适配节点不包含官方接收器内部的身体 IK，不得宣称已有等价的全身跟随。位置量纲、校准零点、根位参考空间都需验证；本规划不预设任何未经实测的换算倍率。

## 5. Unity 调试

Unity 调试面板不再让用户填写控制器或动画文件夹。面板只需要调试对象、组件引用的规则 JSON、输入连接、连接 / 断开、自动开始 / 停止以及原始输入和组件状态观察；规则 JSON 由角色组件决定，面板按钮只负责快速打开和切换到该文件。

选择调试对象后，面板自动在对象及子层级查找 HoVtsParameterReceiver；控制器和 LookAt 从角色已配置的组件引用读取。缺少组件时显示缺失，多份中枢时指出歧义，不偷偷新增组件，也不任意选择第一份。

HoVtsDebugSession 会话后端已实现上述目标查找和输入交付。会话只向已有角色组件送帧，使用接收器内的规则及已有消费者，不自行创建控制器求值对象。它复用现有 Unity 网络输入汇聚，明确将网络 Stopwatch 时钟与 Unity 组件时钟分开；没有新包时由接收器自身推进和检测超时。开始时拒绝正在被其他输入驱动的角色，同一接收器不能同时启动两份调试会话。

主菜单“HoUnityTools/面捕/调试面板”继续使用原面捕调试窗口。配置入口保留场景调试对象、组件引用的规则 JSON、输入连接和进入播放自动开始；面板从对象查找接收器、控制器和姿态组件，提供 JSON 编辑入口、组件状态、原始输入/规则输入/规则输出三段观察、筛选、逐项覆盖与解除，以及停止并交还。切换角色或切换 JSON 会让接收器重新解析新文件；关闭窗口不停止外部角色输入。

组件模式直接复用原 Ho 面捕调试窗口，不再维护一个缩水的第二面板。原窗口的时序录样、逐帧表达式/曲线诊断、单区隔离、授权检查和快捷观察继续保留；角色验收仍由用户在 Warudo 客户端完成。

新录样器 HoVtsTraceRecorder 订阅组件求值完成事件，记录实际求值而非窗口刷新；读取不触发求值，也不按固定时间网格补造帧。面板可设置录样时长和最小采样间隔，0 间隔记录每次实际求值，文件放在 Logs/HoVtsTraces 的 JSONL 中。首行保存规则快照；样本包含原始字典、输入/输出覆盖、输入/输出行的表达式值、曲线值、修饰后值与发布值，以及追踪、超时、原包时间、求值时间、Unity 帧号和规则修订号；末行保存样本数与结束原因。行名的悬浮提示也显示实际求值阶段。

录样由调试宿主持有，关闭面板仍继续。停止调试、达到时长、规则变化、来源接管或域重载会结束记录；不把不同规则或不同输入所有者的数据混入同一条记录。

输入行覆盖作用于规则读取的有效输入；输出行覆盖在有序规则计算结束后作用于最终发布，不改 out() 逐行依赖的中间结果。配置输入值/有效输入值、修饰后输出值/最终发布值可以分别读取，读数不推进求值。覆盖只存在于会话运行期并绑定来源；外部输入接管时不受旧会话覆盖影响，停止旧会话也不会清掉新来源的帧。

规则输出页支持单区隔离：ARKit 表情提供嘴、眉、脸颊、眼睑和眼球范围；其他控制器参数可使用“当前筛选输出”明确选择。隔离仅覆盖选定范围外的表达式输出，值使用该输出行声明的 defaultValue，常量行和范围外参数保持原样。同名行按最后声明者确定是否为常量，防止旧表达式行把最终常量门控关掉。隔离覆盖优先于手动覆盖，但保留原手动值，恢复后重新生效；切换范围不累加旧隔离，规则修改时退出隔离，清除全部覆盖也会退出隔离。录样分别保存手动覆盖、隔离覆盖和合成后的发布覆盖。

面板把输入帧送进角色参数中枢，与 Warudo 运行共享规则执行和控制器后端。调试界面不再维护第二份控制器或规则。角色未配置 LookAt 时仍可调试表情；不强迫角色必须挂齐所有可选消费者。

保留现有三段观察（接收器原始值 / 规则输入 / 规则输出）、手动覆盖、时序录样、单区隔离和逐帧诊断。简化的是配置入口，不能砍掉已验证有效的分析工具。覆盖只存在于调试会话，不反写角色规则；停止调试时解除覆盖并交还写入对象。

规则编辑窗口直接编辑组件引用的 JSON 资产，仍支持独立打开、导入/导出、Undo/Redo 和显式保存。保存 JSON 后所有引用该文件的角色都能重新解析；切换组件引用即可快速换规则。控制器、动画部件制作和手调状态点仍是作者工具职责，本轮不改变已有公式和动画。

组件规则编辑已接入原有输入/输出行编辑器：在 HoVtsParameterReceiver Inspector 或面捕调试面板里点击“编辑规则 JSON”，打开的是组件当前引用的 `.hoface.json`，保留表达式、曲线、修饰符、行编辑与撤销/重做。组件只保存文件引用；旧内嵌表可通过“创建规则 JSON”一次性迁移。

编辑器保存直接写回当前 JSON 文本资产，组件只记录 `TextAsset` 引用；角色预制件不再保存规则副本。切换引用会记录 Undo、标记场景/预制件修改并立即让运行时重新解析。旧内嵌规则迁移时会先写出独立 JSON，再接回组件。

本次只记录迁移目标：不删除旧节点、官方节点、角色文件或用户蓝图，不改 JSON 公式和资源 GUID。后续删除前列清每个旧入口的替代落点，并完成角色端运行验证。

## 7. 命名和打包规范

三个运行时组件的完整类型名固定为：

~~~
Hollow.HoUnityTools.FaceTracking.HoVtsParameterReceiver
Hollow.HoUnityTools.FaceTracking.HoVtsController
Hollow.HoUnityTools.FaceTracking.HoVtsLookAt
~~~

统一约定：

- Ho 前缀 + Vts 输入协议边界 + PascalCase 职责；
- 运行时代码放在运行时程序集，不能放在 Editor；
- 使用 DisallowMultipleComponent；
- 使用空的 AddComponentMenu，由角色预制件显式挂载；
- 不使用 Node、AssetBundle、SolverNode 作为组件名称；
- FastBuild 按完整类型名扫描组件并收集运行时源码闭包；
- FastBuild 组件说明和依赖映射登记三个完整类型；
- 按用户要求把新组件及依赖纳入 Mod 打包支持范围；FastBuild 当前通过预制件扫描、源码闭包、默认勾选和排除规则实现，不假设存在一张尚未找到的单独类型白名单；
- UMod lint 是禁止 API 的静态检查，不是组件白名单；两者分别验证；
- 运行时规则不能依赖 UnityEditor、磁盘路径读取或反射；角色组件不引用 Warudo 程序集；
- Plugin Mod 与 Character Mod 各自编译，完整类型名相同也不代表跨 Mod 类型相同。桥接方式须验证，不能把组件复制进插件后直接强转，也不能用被 UMod 禁止的反射兜底；
- 角色预制件、组件、规则和控制器在同一个 Mod 资产边界内验证。

## 8. 实施顺序

1. 固定 HoVtsParameterReceiver 的序列化字段、规则归属和输入/输出读取接口，先验证跨 Mod 参数桥接及运行时控制器求值。
2. 将现有中间层执行器迁入组件，保证 Unity 与运行时使用同一套语义。
3. 将控制器求值从 HoFace控制求解 迁入 HoVtsController。
4. 将已有 LookAt 约束改成 HoVtsLookAt 的 VTS 输入版本。
5. 保留网络接收和标定节点，实现标定后字典到角色中枢的桥接；现有姿态适配和官方链按需保留。
6. 改造 Unity 调试面板，自动查找角色组件，并打开组件引用的 JSON 规则。
7. 迁移 WTD 角色预制件，确认组件、控制器、动画和规则随角色打包。
8. 删除 HoFT 页面、控制求解节点、旧参数处理节点及旧验证入口；官方姿态节点继续保留。

## 9. 验收标准

- 角色参数中枢和已配置的消费者独立工作，LookAt 可选；外部只需交付标定后的 VTS 帧；
- 多个角色同时运行时参数和控制器状态互不串线；
- 角色不依赖外部控制器 Bundle；
- 蓝图不再选择控制器、不再填写规则文件；
- Unity 调试和运行时使用同一份组件引用的 JSON 和同一套求值语义；
- VTS 断流时形态键、骨骼和 LookAt 都有明确恢复行为；
- FastBuild 产物中三个组件没有 Missing Script，UMod 编译和安全检查通过；
- 官方姿态链可独立保留，自有 LookAt 不与其抢同一批骨骼；无需以替换官方链为完成条件；
- 完整姿态和信号未因形状表过滤而丢失，断流、缺键和多消费者时域行为通过回归；
- Unity 调试只选对象即可取得组件引用的 JSON、规则和控制器，三段读数、覆盖和录样能力保留；
- HoVtsLookAt 的 Scene Gizmo 显示参考坐标、实际骨骼前方和 VTS 目标前方；Warudo 侧 `HoFaceVTS姿态显示` 节点使用与 `HoFace骨骼全量显示` 相同的 `Camera.onPostRender` 叠加路径，在 Game 视图显示头部和双眼的实际/目标轴向；
- 新系统完成后，旧 HoFT Bundle 和 HoFace 控制求解路线不再出现在活文档入口中。
