# HoFace 双文件与制作控制台实施计划

日期：2026-11-03。状态：已启动实施；各阶段完成情况见 [实施记录](HOFACE_IMPLEMENTATION_STATUS.md)，不能将本计划的完成条件当成已通过的验证。

依据：[架构](HOFACE_VALUE_IR_ARCHITECTURE.md) · [UI 技术决策](HOFACE_STUDIO_TECH_DECISION.md)。

## 1. 当前基线

- value 的前身为 `.hoface.json`、`HoVtsRuleEvaluator` 与配套表达式、曲线、修饰符。
- 角色接收器目前引用一份 JSON，表情消费者使用控制器与影子求值。
- `HoVtsLookAt` 读取已处理参数，镜像、校准和方向约定已有回归基线。
- 现有调试有输入/输出覆盖、隔离、录样、校准等能力；新控制台不能只留下基础滑条。
- 网络插件的现行源码同步清单主要为协议解析器；角色规则不在插件中重复执行。

当前基线的实际状态以代码与最近记录为准，不把旧文档中的文件数量和测试数量复制为新系统已通过的证明。

## 2. M0：格式与行为契约

产出：

- value / IR 的最小版本、稳定标识、参数接口与目标绑定约定；
- 第一批实际生产规则、控制点、姿势和录样基线；
- 制作预览与裸值转发的明确输入阶段、所有权与消息边界。

重点：

1. 保住旧规则的行顺序、同名输出、缺键、曲线、时序与方向修正。
2. 确定同一形态键在多个姿势和区域中的合成方式、默认值与内部单位。
3. 裸值入口默认原样；预处理后的测试输入必须明确标记，不能依赖接收端猜测。
4. 既有桥接载荷不随意扩展。转发通过适配器对接角色接收组件，不能把最终权重塞进 raw。

完成条件：用一块真实嘴部数据说明从输入到最终权重的完整计算与归属，格式可校验，不提前建立任意动画系统。

## 3. M1：可移植 value 核心

产出：

- Runtime 中的纯 C# 源码主本；
- 桌面链接编译项目与 Unity 角色宿主适配；
- 固定输入序列和明确时间下的回归。

完成条件：

- 脱离 UnityEngine 可编译与执行；
- 旧生产规则在声明的迁移差异外行为一致；
- 正负值、超 1 姿态、曲线切线、端点、同名输出及过滤状态经过验证；
- 新文件版本严格校验，兼容旧 `.hoface.json` 的迁移不破坏 Unity `.meta` 引用；
- 不向核心引入 WPF、网络、文件 IO 或外部桌面依赖。

## 4. M2：最小 IR 与嘴部迁移

产出：Pose、1D、2D Cartesian、Direct 的有限求值与校验，一块真实嘴部配置。

完成条件：

- 参数轴、阈值、控制点和姿势可编辑并序列化；
- 自由坐标不会被自动网格覆盖；
- 边界、重复点、无环结构、缺省、合成和目标绑定行为有测试；
- 多个贡献写同一目标时无隐式“最后写者获胜”；
- 跨网格同名形态键不会任取一个；
- 从旧控制器提取实际需要的静态姿势与坐标；遇到范围外动画明确报出，不静默采样伪装等价。

不开发 VRC 导出器或通用 AnimatorController 导入器。旧控制器只作为迁移来源和必要的历史对照。

## 5. M3：Windows 编辑器交互原型

按技术决策采用 WPF + .NET 10，使用真实 value 与 IR 数据，而非仅画静态样图。首版窗口与自绘曲线控件已建立，后续仍需接入实时会话和完整 IR 节点选择。

产出：

- 曲线点/切线与二维控制点交互；
- 参数选择、精确数值和姿势权重表；
- 文档脏状态、拖拽撤销、保存与外部改动检测；
- 核心、网络和画面刷新分离。

完成条件：中文、DPI、拖拽、键盘输入和实时输入同时存在时可正常制作；记录实际负载和耗时。候选第三方控件的包版本、许可和分发内容在此时确定。

## 6. M4：默认制作预览闭环

外部程序接收 VTS 或回放，执行 value + IR，向 Blender / Unity 薄适配器发送最终结果。

完成条件：

- 调试不依赖角色内嵌规则组件、控制器或影子台；
- 在 Blender 看面捕、冻结、编辑形态键、恢复及回放，无需先重新导出模型；
- 调整 value 曲线与 IR 控制点可以立即观察；
- 临时覆盖与作品编辑清晰区分；
- 已有隔离、录样、校准、输入诊断能力有迁移对应；
- 关闭预览或切换目标时释放拥有的写入，不遗留持续写入。

Blender 只做薄预览和编辑配合；不再扩建旧混合矩阵，不复制求值数学。

## 7. M5：裸值转发与 Warudo 正式链路

外部程序的第二模式将裸字典交给现有角色接收组件，正式模块自行执行 value + IR。

完成条件：

- 制作预览与裸值转发对同一目标互斥；
- 转发时不额外写最终权重；镜像、校准和倍率不重复；
- 对照使用同一输入阶段、时间与配置版本，分别观察外部和内嵌结果；
- 两份 JSON 引用随角色 Mod 保留，发布运行不需要桌面程序；
- 核心源码经 Unity 编译、UMod 校验、实际角色构建和运行验证；
- 既有网络节点、标定节点、角色输入与 LookAt 行为保留。
- 新增或迁移的运行组件遵循既有 HoVts 命名和 Add Component 分类，登记打包白名单并验证脚本引用。

当前只有协议文件需要在插件仓库中同步，不因本阶段创建第二份插件规则执行器。后续确需增加共享文件时，先更新追踪的清单与漂移检查。

## 8. M6：旧实现退役

前提：新制作闭环好用，角色内嵌链路已验证，旧生产资产完成迁移。

可退役范围：

- 面捕控制器依赖、影子层级、代理 Animator / PlayableGraph；
- Unity 专用规则编辑与旧调试入口中已被替代的部分；
- Blender 旧混合矩阵及其独立求值入口。

保留数据备份、必要迁移工具、角色层级与独立姿态消费者。UI 迁移按能力逐项核对，不能以“新窗口已打开”作为功能完成。

## 9. 三路收口

### Blender / HoTools

正式名称为 **HoFace**。它接收 HoFaceStudio 的最终权重帧，维护需要驱动的物体列表，显示连接状态，并提供清空选中目标形态键权重、目标启用/停用和基型/钉固预检查开关。它不求值 `.hoface.value.json` 或 `.hoface.ir.json`，也不再维护混合矩阵坐标和权重算法。

混合矩阵模块先迁出有效交互和数据，再从 HoTools 面板注册与入口退役。清空形态键属于破坏性操作，必须走 Blender Undo，并在操作名和状态栏中明确显示。

### HoFaceStudio UI

WPF 界面按现代制作工具收口：顶部只保留打开、模式和连接状态；保存、撤销、重做以快捷键为主；value/IR 以左侧目录、中间编辑画布、右侧检查器组织。空文档、断连、无目标和解析错误使用明确的空状态，不让白色默认控件泄露到深色主题。

HoFaceStudio 提供本地 AI 控制通道。命令只操作文档、选择、输入、预览和诊断，不开放任意命令执行。录制、回放、冻结和诊断导出沿用同一结构化接口。

### Unity / HoUnityTools

最终 Unity 调试入口收进 `HoVtsParameterReceiver` Inspector：只在 Play 模式显示连接、追踪、来源和超时状态；找到 `HoFaceStudioRawInput` 时提供启动/停止和自动开始。Unity 侧只接 raw，让 value、LookAt 和其他消费者继续运行。

HoFaceStudio 成为规则与 IR 的正式编辑入口后，退役 `HoFaceProfileWindow`、旧面捕测试窗口、全局调试宿主、旧调试会话和影子求值依赖。删除前先检查引用、迁移能力和测试；旧控制器编辑/绑定工具在 WTD IR 迁移完成前保留为迁移工具。

## 10. 仓库与验证要求

桌面项目放在 `Tools~/HoFaceStudio/`，核心主本放在 Runtime。随附多根工作区同时显示 HoUnityTools 与 Warudo 插件仓库。

实际创建项目时：

- 仅为新桌面项目放开 `.csproj` / 解决方案的入库规则；
- 追踪源码清单、依赖版本、测试与同步脚本；
- 忽略 `bin`、`obj`、publish、录样、用户状态与临时验证工程；
- 不把 WPF / 文本编辑器等 DLL 放进 Unity 导入范围；
- 包、角色构建与网络插件有各自验证边界，单边编译通过不等于跨宿主完成。

每个里程碑提交独立可审查的成果。实际客户端和设备验证的执行人与结果单独记录，不提前宣布验收通过。
