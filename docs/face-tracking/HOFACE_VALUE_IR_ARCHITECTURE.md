# HoFace 双文件架构与外部制作流程

决策日期：2026-11-03。状态：用户确认的目标，已开始实施；实际完成范围见 [实施记录](HOFACE_IMPLEMENTATION_STATUS.md)，本架构不代表整套集成已经完成。

当前可用代码见 [角色组件架构](VTS_COMPONENT_ARCHITECTURE.md)；桌面工具选型见 [UI 技术决策](HOFACE_STUDIO_TECH_DECISION.md)，落地顺序见 [实施计划](HOFACE_IMPLEMENTATION_PLAN.md)。

## 1. 已确认的边界

1. 作品收敛为 `.hoface.value.json` 与 `.hoface.ir.json` 两类文件。
2. 外部 Windows 程序同时编辑两份文件、接收 VTS、执行求值和快速调试。工程内嵌 HoUnityTools 仓库，暂名 HoFaceStudio。
3. 默认制作调试由外部程序完成求值，Blender / Unity 使用薄预览适配器应用结果。现有角色内嵌规则组件只服务于发布运行与专门的链路测试，不充当默认调试后端。
4. 外部程序另有“裸值转发”模式，能向现有角色 VTS 接收器组件交付原始参数，测试实际内嵌链路。
5. 同一份求值核心被桌面程序与角色运行代码使用。角色在 Warudo 内独立执行，不要求最终用户开启作者工具。
6. VRC 导出留待以后。当前不开发任意 AnimatorController 解释器、Unity 编辑代理或控制器双向同步。
7. Blender 旧混合矩阵可简化或退役，Unity 旧专用规则面板也可退役；已有有效制作能力和作品数据需要迁移。

## 2. 两份作品文件

| 文件 | 输入 | 输出 | 作者编辑内容 |
| --- | --- | --- | --- |
| `*.hoface.value.json` | 明确处于指定预处理阶段的跟踪字典 | 表情语义参数，以及独立消费者需要的姿态等参数 | 表达式、响应曲线、组合规则、默认值、参数范围和时序修饰符 |
| `*.hoface.ir.json` | value 层发布的表情参数 | 明确绑定目标的形态键权重 | 静态姿势、混合方式、参数轴、控制点、阈值与权重组合 |

value 回答“跟踪信号怎样变成作者需要的参数”；IR 回答“这些参数怎样组合出角色表情”。IR 不回读 raw，不再次镜像或校准，不重复进行 ARKit 到语义参数的处理。

形态键几何留在 Blender 模型及导出网格中，IR 不复制顶点数据。每份姿势可包含多个形态键；目标标识不能依赖数组下标，也不能在多个同名对象之间任取一个。

程序布局、最近文件、预览目标与临时覆盖属于工作会话设置，不增加第三种必需的作品文件。原始录样可以另存记录文件。

两份文件需要版本、明确的参数接口和校验。具体字段与序列化格式在实现前的小样中定稿，本文不是已经可读取的 schema。

## 3. value 的现有成果与外部参考

现有 `.hoface.json` 是 value 层的迁移来源，尽量保留已经验证的表达式、输入/输出行顺序、同名输出、曲线、修饰符、默认值和缺键行为。不能为了改后缀重写全部规则。

保留现有已修正的方向归一化：头姿与 ARKit 左右一致，镜像、校准和姿态量纲各归其层。不能把所有值统一钳到 0–1 或 −1–1。

参考 VBridger 式中间参数处理体验及 VRChat 新原生面捕规则，借鉴其分层与编创体验，不承诺原生文件互读。

官方资料核查于 2026-11-03：

- [VRChat 2026.4.1 / build 1763](https://docs.vrchat.com/docs/vrchat-202641)：2026-10-28 正式上线原生面捕。
- [SDK 3.10.6](https://creators.vrchat.com/releases/release-3-10-6/)：2026-10-30 发布相关编创功能。
- [Face Tracking 作者文档](https://creators.vrchat.com/avatars/face-tracking/)：支持参数组合、自定义表达式、编辑器预览与直接形态键驱动。

VRChat 的多个集合驱动同一形态键时取最大值；这不自动成为 HoFace IR 的合成规则。HoFace 的 Direct 相加、归一化和默认值需要按自己的作品与测试明确。

## 4. IR 第一版范围

先覆盖当前需要的静态形态键表情：

- **Pose**：一组明确目标的形态键权重。
- **1D**：参数、手动阈值与子项引用。
- **2D Cartesian**：两个参数、可自由编辑的控制点与子项引用。
- **Direct**：子项权重或权重参数，以及明确的归一化/叠加约定。

节点可嵌套，引用必须无环。姿势、节点与绑定有稳定标识，显示名称改变不应破坏引用。第一版不扩大到状态机、时间片段、事件、材质、物体开关或骨骼动画。

必须确定的数学行为包括：重复目标的合成、空姿势、缺省参数、零权重、边界与超范围输入、重复点位、目标所有权、内部权重单位。模式名称相同不等于算法已经一致，不以旧 Blender 模块的近似结果替代定义。

控制点坐标是作品数据。网格只用于初始化，不能在刷新或载入时覆盖作者手调位置。节点布局、视口缩放和预览游标不是混合坐标。

## 5. 两种调试模式

### 5.1 制作预览：默认

```text
VTS / 录样
  → 外部程序输入预处理与校准
  → 外部 value 求值
      ├─ 语义参数观察
      └─ 外部 IR 求值
           → 最终权重帧
           → Blender / Unity 薄预览适配器
```

角色内嵌 value/IR 模块不参与这条调试链。预览端只做目标查找、单位转换、应用与释放，不再解释规则，不运行影子 Animator 或控制器。

现有嵌入模块拥有的正式写入与制作预览不能同时接管同一目标。切换模式要明确移交所有权并释放旧写入。

首个预览闭环限于形态键。既有 LookAt 等消费者不在这一步重写；需要扩展预览输出时，单独明确其输入阶段与写入所有权。

### 5.2 裸值转发：角色链路测试

```text
VTS / 录样
  → 原始字典转发
  → 宿主薄桥接
  → 现有 HoVtsParameterReceiver 接收入口
  → 角色内嵌 value / IR
  → 角色实际输出
```

这里的裸值指协议解析后的原始字典，尚未执行 value 或 IR；默认不隐式叠加外部镜像、校准、倍率。若需要测试带输入预处理的链路，明确选择预处理阶段并在会话中显示，不能两端重复处理。

现有角色接收入口通常接收经过外部标定的字典。适配器需区分上述输入阶段；对照测试必须使用同一阶段的数据，不能把“裸手机帧”与“标定后帧”的差异误判为求值器漂移。

该模式目的在于验证角色内嵌模块。外部程序不向同一目标额外发送最终权重。Blender 若没有对应的角色链路，就不提供假装等价的回退模式。

目标是角色参数接收器组件，不是把两份作品 JSON 塞进网络接收节点。优先保留既有帧桥接接口；不能再次通过隐式消息或随意扩展载荷改变参数含义。

## 6. Warudo 正式运行

```text
现有 VTS 接收节点与输入预处理
  → 现有标定、角色输入桥接
  → 角色内嵌 value 求值
      ├─ IR 求值 → 角色形态键
      └─ HoVtsLookAt / 其他既有消费者
```

两份 JSON 由角色组件引用并随角色 Mod 打包。外部控制台不参与用户正式运行。

网络插件仍负责接收、标定、节点交付和诊断；规则与 IR 属于角色运行模块。当前插件的 `Core/PORTED.md` 已明确该分工，不应为了“共享核心”再次把全部求值器复制进插件。

现有 HoVTS 角色层级、输入桥接、追踪丢失、超时、停用恢复与范围内写入语义应保留。IR 替换表情控制器求值，不顺手改动已稳定的姿态系统。

## 7. 共享代码与会话语义

最终共享核心为可脱离 UnityEngine 的 C# 源码。桌面程序、Unity 角色组件与打包后的角色使用同一语义实现，各自拥有独立的求值状态。

现有规则代码仍使用 Unity 曲线、数学和时钟相关能力，不能将当前程序集直接视为普通 EXE 已可复用。提取时需要覆盖曲线切线、端点钳制、延迟、平滑、保持、超时与重置行为。

JSON 读写以已验证的解析语义为基线，发布数据路径不改用 `JsonUtility`。新增 JSON 依赖前必须验证 Unity / UMod 支持、角色打包和嵌套数据读取，不能只在桌面端验证成功。

核心只处理数据与显式时间，不负责文件 IO、网络、UI 或场景对象。输入输出阶段、帧序号、配置版本和时间来源需要明确。一次核心会话只推进一次时间，多个预览端不能让过滤状态重复前进。

制作预览与原始转发采用不同消息类型或明确的阶段标记。不能把处理后的参数或最终权重包装成 raw 交给接收器。

配置先校验再替换当前会话。单文件原子写入不等于两文件事务；成对参数接口要一起检查。外部 AI 改文件时，控制台需检测外部变更并防止覆盖未保存编辑。

## 8. 编创与退役原则

外部控制台统一提供 value 编辑、IR 图形编辑与调试。人能拖曲线和控制点，AI 能修改文本；图形编创是首版功能。

要迁移已有的覆盖、区域隔离、录样、校准和连接诊断，并补齐样本回放。冻结原始样本与锁定语义输出需要区分，避免以为冻结后过滤器仍在移动。

Blender 旧混合矩阵和 Unity 专用规则面板不是兼容要求。可迁移有价值的坐标、姿势和交互代码；新流程覆盖有效能力后退役旧实现。

面捕影子台、代理 Animator、PlayableGraph 和控制器逐属性抄写在 IR 直接求值后退出主链。删除范围限于被替代的面捕实现，迁移前保留作品数据与回滚基线。

第一阶段验收：在 Blender 看面捕，冻结并改一份嘴型，恢复或回放后立即观察；修改 value 曲线或 IR 控制点也即时反映。相同绑定下的几何编辑无需先将模型重新导入 Unity。
