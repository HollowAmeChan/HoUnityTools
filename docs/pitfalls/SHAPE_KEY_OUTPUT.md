# 形态键输出：写死 100、清场、族别混用

正本是 [眨眼约束](../BLINK_CONSTRAINT.md)（合并方式 / 清场）与 [注视约束](../LOOKAT_CONSTRAINT.md)（族别 / 重复注册）。

## 1. "形态键怎么调都是 100"

合法区间是 `0..100`，一个键上可能同时有好几个写者，求和在 100 处夹断 —— 但**来源有三种**，对策完全不同：

| 来源 | 特征 | 对策 |
| --- | --- | --- |
| 单路自己就拉满 | 基准 0 + 我们 100 → 100，没被削 | 设计如此；要余量就压增益 / 输出上限，或 ramp 别用「放大」 |
| 多路叠加被夹断 | 两路要 80 / 70，加起来 150 → 夹成 100，比例与超调全没了 | 合并方式换**软饱和**（永远不到 100，超调看得见）或**按比例分配**（一起缩、比例不变） |
| 外部基准已占满 | 基准本身 60~100（动画 / 面捕 / VRChat 表情在写） | 按比例分配按剩余空间分；或该键改用 `Override`；并确认读的是基准快照 |

**合并方式**只作用在我们这一路（`sum = 0` 时输出恒等于基准）：

| 取值 | 规则 | 请求 100 的结果 |
| --- | --- | --- |
| `Saturate`（默认） | 求和后夹到 0..100 | 100 |
| `SoftClip` | 80 以上软压缩 `80 + 20·(1 − e^−(x−80)/20)` | ≈ 93（渐近但永远不到 100） |
| `Normalize` | 超过剩余空间时各路同比例缩小 | 100，且 80/70 变成 53/47 |

写入器每帧记「基准 / 我们请求的原始和 / 实际写出值 / 是否被削」，面板调试区直接列出来 ——
看到「被削」就是多路或基准在打架；看到「基准 0 + 我们 100 → 100」就是单路到顶。

## 2. 没人写的时候，键不会自己回原样

症状：**规则一关，键还停在最后一次写的值上，怎么都不回 0**。

必须有人**硬写**回去（不看写入阈值）：

| 时机 | 行为 |
| --- | --- |
| 规则被关掉（`Enabled = false`），目标还挂在写入器里 | 求和里这一路变 0，键自然回到基准（前提是基准没被我们自己污染） |
| 规则被删 / 目标被移除 / 网格列表变化 | 重建收尾时硬写回基准 |
| 组件禁用、取消「允许写入」、`ResetState()` / 面板「重置」 | `RestoreWritten()` 把这一轮写过的键全部硬写回基准 |

关键不变量：**重建不许把我们自己的输出当成外部基准**。写入器跨重建记住"上一轮写过哪些键、写之前的基准是多少"；
没有这条，任何一次重建都会把当时的输出冻成新基准。我们**只还自己拿过的键**（`EverWritten` 为假的一个都不碰）。

## 3. 同一个键注册两次 = 写两遍

症状：**中等角度就直接顶到 100**。
原因：预设给「双眼共用键」的模型在左右两格填了同一个键名，写入器把同一个键注册了两次 → 两路各写一份 → 求和翻倍。
现在同名同增益的两个槽只注册一次。自己手填时也要检查。

## 4. 左右族与内外族不要混用

- **左右族**（相对头）：`EYES_LOOK_LEFT_L/R`（Meta）、`Eye_Left_Left/Right`（SRanipal）、`LookLeft/Right`（VRM）。
- **内外族**（相对眼球）：`eyeLookIn/Out*`（ARKit）、`EyeLookIn_L/R`（PICO/OpenXR）。

混族去合成双极驱动时，两把键的符号关系对不上，**某些方向会互相抵消**（面板会警告，但不做自动换算）。

## 5. 长帧：停帧后爆掉

`maxStep` 没分子步时，一个长帧就能把积分推出发散区，而且状态里一旦留下 `NaN` 就自己不会恢复。
完整的三个坑与数字见 [液体 shader 契约](LIQUID_SHADER.md) §1。

## 6. 中间层曲线的纵轴是**参数值**，不是百分数

症状：给 `ARKit/jawOpen` 那一行配了一条 `0..100` 的曲线，权重算出 **210**（= 参数 2.107 × 片段里的 100）
—— 而且平滑没到位时它看着还"像那么回事"，更难发现。

原因：**参数进了混合树就是子权重**，片段里那个 100 是"姿势"，两套单位。直通行（`ARKit/<键>`）
的曲线就该是 `0..1 → 0..1`；写成 `0..100` 等于把权重放大 100 倍。

怎么办：**看这个参数被谁消费** —— 当树的子权重就是 0..1；想要"百分数那种感觉"，那是片段的事。
（实测现场：`weight=210.6979, param=2.1070`。）
