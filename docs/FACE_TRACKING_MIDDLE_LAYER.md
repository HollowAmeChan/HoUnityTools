# 面捕中间层处理

日期：2026-09-25（按"两类行 + 配置文件是映射表的唯一来源"这一版重写）。
讲"值是怎么被加工"的就是这一份；能力边界见 [混合树的能力边界](BLEND_TREE_LIMITS.md)，
怎么用见 [面捕工作流](FACE_TRACKING_WORKFLOW.md)。

## 1. 一句话

**参数进、参数出。** 中间层只搬运与加工**值**，从不碰姿势 —— 姿势是混合树的活。

形状照 **VBridger**（同类里最成熟的那个，我们逆过它的存档与 UI，见
[归档研究](archive/VBRIDGER_MIDDLE_LAYER_RESEARCH.md)）：
**每一行 = `名字 = 曲线(表达式(变量…))` + 一串有序修饰符**。一份配置里有**两类这样的行**：

| 行 | 左值（写出去的） | 变量（读进来的） | 干的事 |
| --- | --- | --- | --- |
| **输入行** | **规范名**（`jawOpen`、`headRotX`…） | 手机发来的**线名**（`JawOpen`、`Rotation_x`…） | **改名 + 量纲 + 姿态分量**，全在这一层 |
| **输出行** | **控制器参数名**（`ARKit/jawOpen`…） | 规范名（也允许直接写线名） | 参数怎么来、曲线怎么整、平滑/分档 |

接收端**只交原样**（线名 + 原值 + `FaceFound` / 热键）：它不做改名、不做换算、不做合并。
这条是硬规矩 —— 换个设备只改配置，不动代码。

## 2. 为什么它必须存在（不是我们发明的活）

混合树能表达的只有"**参数的多项式 + 分段线性**"：加权和、嵌套门控相乘（`a·b`）、折线。
它做不到 `min` / `max` / 除法 / 指数与任意曲线，**没有记忆**（平滑、弹簧、迟滞），
更不能**产出参数**（只能写对象属性）。所以"值"的加工必须在外层 —— 这一层就是它。
判据与实测见 [混合树的能力边界](BLEND_TREE_LIMITS.md) §1–§5、
[踩过的坑 · 混合树](pitfalls/BLEND_TREE_TRAPS.md)。

## 3. 四层，各归各的

| 层 | 跟什么走 | 存在哪 | 里面有什么 |
| --- | --- | --- | --- |
| **输入行** | **这台设备 / 这张脸**（换模型不用重做） | 配置文件 `.hoface.json` 的 `inputs` | `规范名 = 曲线(表达式(线名…))` + 有序修饰符 |
| **通道层**（过渡期） | 这台角色 | 调试设置的内存字段（`HoFaceDebugSettings.channels`） | 52 个规范名的**模式**（实时 / 手动 / 保持 / 中性 / 交还）、中性值、**输入曲线** |
| **输出行** | **这份控制器** | 配置文件 `.hoface.json` 的 `outputs` | `参数名 = 曲线(表达式(规范名…))` + 有序修饰符 |
| **断流 / 回中性** | 这台角色 | 调试设置（`staleSeconds` / `neutralFadeSeconds`） | 多久没收到包算断流、多快滑回中性 |

⚠️ 通道层是**过渡期字段**：面板上目前**没有入口**，而且它**不落盘**（进播放模式的域重载之后就回到默认）。
按已定的方向，它的"输入曲线"该并进**输入行**（那一层本来就该负责这台设备的手感），
模式与中性值也会随之下沉。用例还在这层上做断言（`Tests~/FaceTrackingValidation.cs`）。

**输入曲线**（横轴 = 原始输入 0..1，纵轴 = 整形后的输入）：它就是"我的脸打不满 1"的解法，
也顺手把静止时的小抖动压掉 —— 这正是 VBridger 的 Input Curve。**增益被它取代了**：
增益只是曲线的一段直线，而曲线能同时表达"打不满"、"压噪声"、"整体放大"，而且是**数据**。

## 4. 固定步骤（顺序不可换）

```
手机线名原值（接收端只交原样）
  → 输入行：curve( expression( 线名… ) ) + 修饰符        （配置文件 inputs）
  → 通道层（过渡期）：模式 / 输入曲线 / 断流回中性         （调试设置 channels，不落盘）
  → 输出行：curve( expression( 规范名… ) ) + 修饰符       （配置文件 outputs）
  → 写进影子 Animator 的参数
```

两条纪律：

- **轴是参数算术，必须在表达式里做完**（`开合 = eyeBlinkLeft − eyeWideLeft`）—— 树只消费参数。
- **平滑在输出侧、按行给**（不再有"眼睑组一个时间常数"）：眼球要跟得紧、眼睑要稳、嘴更黏，
  那是**每一路自己的手感**。

## 5. 一行长什么样

| 字段 | 说明 |
| --- | --- |
| `parameter` | 写出去的名字。**输入行**里是规范名，**输出行**里是控制器参数名（控制器里没有这个名字就跳过 —— 不猜也不补） |
| `expression` | 表达式，变量就是上一层给的名字（输入行读线名，输出行读规范名） |
| `curve` | 响应曲线：横轴 = 表达式的值，纵轴 = **写出去的值**。范围之外按端点算（不外推） |
| `modifiers` | 有序：`Smooth`（秒）/ `Steps`（trigger / target / hold / threshold）/ `Delay`（**未实现**） |

⚠️ **不写 `curve` 不等于"直通"**：默认曲线是 **`0..1 → 0..1` 线性**（`HoFaceOutput.curve = AnimationCurve.Linear(0,0,1,1)`，
`HoFaceCurve.Transfer` 先按端点夹取再求值）—— 所以**度数、米、任意量纲的行必须自己写 `curve`**，
否则会被夹成 0/1（负值一律 0）。2026-09-25 实测现场：临时写的调试配置里
`headRotX ← Rotation_x`（度）没写曲线 ⇒ 手机发 `Rotation_x = 3.118`，输出端恒为 0，
表现为"头姿一直是 `(0.0, 0.0, 0.0)°`、`Head Position` 一直 `(0,0,0)`"，而形态键（本来就是 0..1）一切正常 ——
**症状看起来像"头那部分没接线"，其实是曲线把值夹没了**。修法：给那几行写宽范围恒等曲线
（角度 `±180 → ±180`、位置 `±100 → ±100`，`inT/outT = 1`）。

⚠️ **输出行曲线的纵轴是"参数值"，不是百分数**：参数进了混合树就是**子权重**，片段里那个 100 是另一回事
（树采的是姿势）。所以 `ARKit/eyeBlinkLeft` 这种直通行，曲线就是 `0..1 → 0..1`；
把纵轴写成 `0..100` 会让权重变成 100 倍（实测踩过：权重 210 = 参数 2.107 × 片段 100）。

### 5.1 表达式语言（照 VBridger）

- 运算符：`+ - * / ^`、比较 `< <= > >= == !=`、逻辑 `&&` `||`、括号、单引号 `'…'`（惰性嵌套表达式）。
- 函数：`sin cos tan asin acos atan atan2 sinh cosh tanh abs sqrt log log10 exp round floor ceil sign
  min max clamp approx lerp rand time if`。
- `if('(a>0.5)&&(b>0.8)', 真, 假)` **只算被选中的那支**；`time(i,m)` 按帧计数。
- **未知变量按 0、非有限结果折 0、除零按 0** —— 它跑在每帧的管线上，绝不抛异常（错在解析期报）。
- 两个例子：
  `eyeBlinkLeft - eyeWideLeft` —— 双向轴；
  `0.75 - 0.75*eyeBlinkLeft + 0.25*eyeWideLeft` —— 别人血统那种加权式（VRCFT 的 `EyeLid`），**一行就够**。

### 5.2 修饰符

| 修饰符 | 干什么 | 参数 |
| --- | --- | --- |
| **平滑 Smooth** | 指数平滑（一阶低通），压抖动 | 时长（秒） |
| **分档 Steps** | 翻页式：过 `trigger` 跳到 `target`，掉回 `threshold` 之下才退，触发后至少保持 `hold` | trigger / target / hold / threshold |
| 延迟 Delay | **未实现**（数据字段已留位，面板会标出来） | 时长（秒） |

## 6. 配置文件

一份可读 JSON，扩展名 `.hoface.json`，**放哪都行**。它是**磁盘上的普通文件**（不是 `TextAsset` 引用）：
Unity 侧与 Warudo 侧读的是**同一个文件** —— 这是"面板里是什么、Warudo 里就是什么"的物理保证。
设置里存的是它的**路径**；面板把它当**必填总闸**（空着就把下面各栏锁住）。

⚠️ **精确语义**（两类行不一样，`HoFaceDebugSettings.Inputs()/Outputs()`）：

| | 取哪一份 | 有配置文件、但那一类是空的 |
| --- | --- | --- |
| **输入行** | `有配置文件 ? 它的 inputs : 内置默认表` | 用它的空表 ⇒ **等于不做改名**（规范名必须与线名同名） |
| **输出行** | 有配置文件**且至少一行**才用它，否则内置默认表 | 退回内置默认表（52 个 `ARKit/<规范名>` 直通 + 4 根眼睑轴） |

也就是说"没指定配置文件"**不是不能跑**：那时两类行都吃内置默认表（输入行两种协议都有，
含 VTS 的 PascalCase 线名）。真正会咬人的是**指定之后漏了线名** —— 见
[踩过的坑 · 面捕流水线](pitfalls/FACE_TRACKING_PIPELINE.md) §3。

```json
{
  "format": "ho-face-middleware",
  "version": 1,
  "displayName": "ho-2d-test1",
  "notes": "配对：吃 ARKit/* 的控制器",
  "inputs": [
    { "parameter": "jawOpen", "expression": "jawOpen * 0.01", "notes": "iFacialMocap（历史行，现在不接）" },
    { "parameter": "jawOpen", "expression": "JawOpen", "notes": "VTS 手机" },
    { "parameter": "headRotX", "expression": "Rotation_x", "notes": "VTS 手机；弧度还是度由你自己在这行决定" }
  ],
  "outputs": [
    {
      "parameter": "ARKit/jawOpen",
      "expression": "jawOpen",
      "curve": { "keys": [ { "t": 0, "v": 0, "inT": 0, "outT": 0 },
                           { "t": 1, "v": 1, "inT": 0, "outT": 0 } ] },
      "modifiers": [ { "kind": "smooth", "seconds": 0.03 } ]
    },
    {
      "parameter": "Ho/Drive/Lid/Left/BlinkWide",
      "expression": "eyeBlinkLeft - eyeWideLeft",
      "curve": { "keys": [ { "t": -1, "v": -1 }, { "t": 1, "v": 1 } ] },
      "modifiers": []
    }
  ]
}
```

- **同名多行：最后一行生效**（用户覆盖用）。上面例子里 `jawOpen` 出现了两次（两套协议的线名），
  实际哪一行算数取决于手机在发哪一套 —— **缺键语义**：表达式引用到的线名只要有一个这一帧没来，
  这一行就**不写**（保持上一帧、并标记为不新鲜），所以两套协议的行同时存在是安全的。
- **一旦指定了配置文件，线名 → 规范名就只认它的 `inputs`**，不会再拿内置默认表来补。
  `inputs` 为空 = 不做改名（那时规范名必须与线名同名）。
- `format` + `version` 给以后的兼容留位：**认不出的字段忽略**，认不出的修饰符 `kind` 会被点名。
- 曲线在文件里就是关键点列表（`t` / `v` / `inT` / `outT`）；**关键点的范围就是这条曲线的定义域**。
- 不加密、不带魔改编码 —— 它是数据，就该能 diff、能用手改、能发给别人。

## 7. 面板与窗口

- **主面板「对象」栏**：配置文件对象（路径 + 「选…」/「新建」）—— 面板把它当**必填总闸**（空着下面各栏都锁住），
  但代码里有内置默认表兜底（见 §6 的表）；读不进来时这里直接给原因。
- **主面板「配置详情」栏**：摘要就是 `输入行 N · 输出行 M`，然后把**输入行与输出行**逐行摊开
  （只读：规范名 / 输出、曲线点数、修饰符链）。解析器报的非致命问题（比如认不出的修饰符）也在这一栏。
- **配置文件窗口**（菜单 `HoUnityTools/面捕/配置文件`）：左边是可滚动的行列表
  （搜索 / 新增 / 删除 / 上下移 / ⚠ 标记），右边是选中那一行的**表达式、变量、曲线、修饰符**；
  「保存」写回那个文件。列表顺序 = 写参数的顺序，修饰符顺序 = 串起来的顺序。
- **实时输入**（线名 / 值 / 距上帧）在主面板的「参数输入」栏，**纯调试读数**。
  ⚠️ 过渡期：52 个通道的**模式 / 手动值 / 输入曲线**目前面板上没有入口（字段还在、用例还在用），
  按已定的方向它们该并进输入行。

## 8. 隐式处理：哪些东西在树里、看不见

| 隐式处理 | 为什么看不见 | 现在怎么办 |
| --- | --- | --- |
| **眼睑合并**：`blink / wide / squint` 被写进**同一棵 2D 树**的姿势里 | 它发生在**树**里，而树是控制器作者编的 | 「控制器编辑」页的详情报得出实况；要不要做开关见下条 |
| **眨满时眯眼被权衡掉**：两键加和从 200 降到 ~110 | 树的性质（权重和恒 1），没有对应代码 | 要精确控制就把那一格姿势补上（[控制器结构](FACE_TRACKING_CONTROLLER_STRUCTURE.md) §3.2） |
| **`wide` 与 `blink` 压成一根轴** | `开合 = blink − wide` 是**配置里的表达式**，不是代码 | 看得见（配置里那一行就是它）；它是有损降维，但两根轴已经是树的上限（没有 3D 树） |
| **线名 → 规范名的改名与量纲** | 它是配置文件里那一行 `expression` | 看得见：主面板「配置详情」栏逐行列出来 |

**现在没有区域门控。** 哪些键算数由**使用者自己的混合树/参数**决定，我们不再替谁注入开关
（曾经有过一套 `Ho/Drive/Gate/*` 参数，已删）。

## 9. 还没做 / 明确不做

| 项 | 状态与理由 |
| --- | --- |
| **延迟（Delay）修饰符** | 数据留位、**未实现**（面板标注）。要加就是几十行 FIFO |
| **行之间互相引用** | **不做**。VBridger 允许（它把每行结果发布成全局变量），代价是**没有环检测**、顺序靠偶然；我们的表达式只读上一层 |
| **vector 模式**（一行写 X/Y/Z） | 不做：我们要的就是"一个名字一行"，VMC 那种三维向量不在这条链上 |
| **每行的 `min`/`max` 声明** | 不单独声明：**曲线关键点的范围就是定义域**，超出按端点算（VBridger 那份声明主要是给 VTS 报参数范围） |
| **通道层的模式 / 手动值 / 输入曲线** | **过渡期**：字段还在（用例在用），面板上没有入口；方向是并进输入行 |
| **对接下游平台的名字与范围**（VTS / VMC-VRM / Live2D `Param*`） | 本期不做，但**已经查清**：逐行权威表见 [**参数标准表**](PARAMETER_STANDARDS.md)（官方 URL 逐条核对）—— 喂 VTS 就写它的**追踪参数**（`FaceAngleX`/`MouthOpen`…，不是 `Param*`），喂 VMC/VRM 就写 **ARKit 52**；VBridger 那十种公式我们的"表达式 + 曲线"都能表达（见 [VBridger 的输入 / 输出参数格式](archive/VBRIDGER_IO_VOCABULARY.md)） |
